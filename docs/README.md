# 文档规范指南

本目录存放项目的设计文档、计划文档、进度文档和变更记录。所有文档必须遵循本规范。

---

## 一、核心文档概览

| 文档                 | 用途                             | 更新频率   |
| -------------------- | -------------------------------- | ---------- |
| `design.md`          | 总体设计索引，链接各模块设计文档 | 新增模块时 |
| `design_<module>.md` | 模块设计文档                     | 设计阶段   |
| `plan.md`            | 开发计划、里程碑、任务分解       | 规划阶段   |
| `progress.md`        | 开发进度、完成状态               | 每日/每周  |
| `changes.md`         | 重要变更记录、决策原因           | 变更发生时 |

---

## 二、设计文档 (design.md)

### 2.1 文档定位

设计文档描述系统架构、模块设计、业务流程、数据模型和界面设计。**设计文档是给人看的，不是给机器执行的。**

### 2.2 命名规范

| 文档类型   | 命名格式                         | 示例                                |
| ---------- | -------------------------------- | ----------------------------------- |
| 总体设计   | `design.md`                      | `design.md`                         |
| 模块设计   | `design_<module>.md`             | `design_agent.md`                   |
| 子模块设计 | `design_<module>_<submodule>.md` | `design_server_web.md`              |
| 功能设计   | `design_<module>_<feature>.md`   | `design_server_web_agent_detail.md` |

### 2.3 必须包含的章节

```
# <模块名称> 设计文档

## 1. 概述
   - 模块职责（一句话说明）
   - 核心功能（列表形式）
   - 与其他模块的关系

## 2. 架构设计
   - 模块结构图（txt 流程图）
   - 核心组件说明（表格形式）
   - 依赖关系

## 3. 数据模型
   - 数据表设计（表格形式）
   - 字段说明（表格形式）
   - 关联关系（文字描述）

## 4. 业务流程
   - 核心流程图（txt 流程图）
   - 流程说明（文字描述）
   - 异常处理（表格形式）

## 5. 接口设计
   - API 列表（表格形式）
   - 请求/响应字段（表格形式）
   - 错误码定义（表格形式）

## 6. 界面设计（仅前端相关模块）
   - 界面布局（txt 线框图）
   - 交互说明（文字描述）
   - 设计图引用（SVG 图片链接）

## 7. 安全设计（如适用）
   - 认证授权
   - 数据安全
   - 审计日志
```

### 2.4 禁止事项（重要）

设计文档及其所有子文档**严格禁止**包含任何代码：

| 禁止内容                   | 示例                       | 替代方案            |
| -------------------------- | -------------------------- | ------------------- |
| Go 代码                    | `type Agent struct {...}`  | 用表格描述字段      |
| JavaScript/TypeScript 代码 | `const agent = {...}`      | 用文字描述逻辑      |
| Vue/React 模板             | `<template>...</template>` | 用 txt 线框图       |
| SQL 语句                   | `CREATE TABLE...`          | 用表格描述表结构    |
| 配置文件                   | TOML/YAML/JSON             | 用表格列出配置项    |
| Shell 命令                 | `bash scripts/...`         | 在 README.md 中说明 |
| API 请求示例               | `curl -X POST...`          | 用表格描述请求字段  |

**正确示例**：

```markdown
### 3.1 Agent 表

| 字段           | 类型     | 必填 | 说明                   |
| -------------- | -------- | ---- | ---------------------- |
| id             | int64    | 是   | 主键，自增             |
| agent_name     | string   | 是   | Agent 名称，唯一索引   |
| status         | string   | 是   | 状态：online / offline |
| last_heartbeat | datetime | 否   | 最后心跳时间           |
```

**错误示例**：

```markdown
### 3.1 Agent 表

type Agent struct {
ID int64 `gorm:"primaryKey"`
AgentName string `gorm:"uniqueIndex"`
}
```

### 2.5 txt 流程图规范

使用 txt 字符绘制流程图，用于描述业务流程、数据流向、模块交互：

```txt
┌─────────────────────────────────────────────────────────────┐
│                     Agent 注册流程                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   Agent 启动                                                │
│       │                                                     │
│       ▼                                                     │
│   ┌─────────────┐                                          │
│   │ 读取配置文件 │                                          │
│   └─────────────┘                                          │
│       │                                                     │
│       ▼                                                     │
│   ┌─────────────┐    失败    ┌─────────────┐              │
│   │ 连接 Server │──────────►│ 重试（3次） │              │
│   └─────────────┘            └─────────────┘              │
│       │ 成功                       │ 超限                  │
│       ▼                            ▼                       │
│   ┌─────────────┐            ┌─────────────┐              │
│   │ 发送注册请求 │            │  退出程序   │              │
│   └─────────────┘            └─────────────┘              │
│       │                                                     │
│       ▼                                                     │
│   ┌─────────────┐                                          │
│   │ 启动心跳循环 │                                          │
│   └─────────────┘                                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**流程图元素**：

| 元素      | 符号              | 用途       |
| --------- | ----------------- | ---------- |
| 开始/结束 | `[ 文字 ]`        | 流程起止点 |
| 处理步骤  | `┌───┐ │ │ └───┘` | 操作或处理 |
| 判断分支  | `◇` 或文字标注    | 条件判断   |
| 流向箭头  | `│ ▼ ► ◄ ▲`       | 流程方向   |
| 连接线    | `─ │ ┌ ┐ └ ┘ ├ ┤` | 连接元素   |

### 2.6 txt 界面线框图规范

使用 txt 字符绘制界面布局，用于描述前端页面结构：

```txt
┌─────────────────────────────────────────────────────────────┐
│  Agent 详情                                    [编辑] [删除] │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌─ 基本信息 ──────────────────────────────────────────┐   │
│  │  名称: agent-01          状态: ● 在线               │   │
│  │  IP: 192.168.1.100       最后心跳: 2026-01-11 10:00 │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  ┌─ 服务列表 ──────────────────────────────────────────┐   │
│  │  名称        端口      状态      操作               │   │
│  │  ─────────────────────────────────────────────────  │   │
│  │  web-app     8080      运行中    [停止] [删除]      │   │
│  │  database    3306      运行中    [停止] [删除]      │   │
│  │                                                     │   │
│  │                              [+ 添加服务]           │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**界面元素**：

| 元素     | 符号           | 用途             |
| -------- | -------------- | ---------------- |
| 按钮     | `[按钮文字]`   | 可点击按钮       |
| 输入框   | `[________]`   | 文本输入         |
| 下拉框   | `[选项 ▼]`     | 下拉选择         |
| 复选框   | `[x]` 或 `[ ]` | 多选             |
| 单选框   | `(●)` 或 `( )` | 单选             |
| 状态指示 | `●` `○` `◐`    | 在线/离线/加载中 |
| 分隔线   | `───────`      | 内容分隔         |
| 卡片边框 | `┌─ 标题 ─┐`   | 内容分组         |

### 2.7 SVG 设计图规范

复杂的界面设计需要配套 SVG 设计图，存放在 `/images/` 目录。

**命名规范**：`design_<module>_<feature>.svg`

| 模块       | 功能         | 文件路径                                     |
| ---------- | ------------ | -------------------------------------------- |
| server_web | agent_detail | `/images/design_server_web_agent_detail.svg` |
| server_web | service_list | `/images/design_server_web_service_list.svg` |
| desktop    | login        | `/images/design_desktop_login.svg`           |
| desktop    | main         | `/images/design_desktop_main.svg`            |

**在文档中引用**：

```markdown
## 6. 界面设计

### 6.1 Agent 详情页

[此处放置 txt 线框图，描述基本布局]

详细设计图：

![Agent 详情页设计](../images/design_server_web_agent_detail.svg)
```

**SVG 制作要求**：

| 要求 | 说明                          |
| ---- | ----------------------------- |
| 格式 | 矢量 SVG，不使用位图          |
| 尺寸 | 宽度 800-1200px               |
| 字体 | Arial, sans-serif（通用字体） |
| 颜色 | 使用清晰的颜色区分元素        |
| 图例 | 包含必要的图例说明            |

## 三、计划文档 (plan.md)

### 3.1 文档定位

计划文档描述开发计划、里程碑、任务分解和时间安排。**只描述"做什么"和"什么时候做"，不描述"怎么做"。**

### 3.2 必须包含的章节

```
# 开发计划

## 1. 版本规划
   - 版本号
   - 目标功能（列表）
   - 预计时间

## 2. 里程碑
   - M1: 里程碑名称（日期）
   - M2: 里程碑名称（日期）

## 3. 任务分解
   ### 3.1 Phase 1: 阶段名称
   - [ ] 任务 1
   - [ ] 任务 2

   ### 3.2 Phase 2: 阶段名称
   - [ ] 任务 3
   - [ ] 任务 4

## 4. 依赖关系
   - 任务依赖说明
   - 阻塞项

## 5. 风险评估
   - 风险项
   - 应对措施
```

### 3.3 禁止事项

| 禁止内容 | 说明                           |
| -------- | ------------------------------ |
| 代码片段 | 计划文档不包含任何代码         |
| 实现细节 | 只描述"做什么"，不描述"怎么做" |
| 技术方案 | 技术方案放在设计文档           |

## 四、进度文档 (progress.md)

### 4.1 文档定位

进度文档记录开发进度、完成情况和当前状态。**保持简洁，便于快速了解项目状态。**

### 4.2 必须包含的章节

```
# 开发进度

## 当前状态
**版本**: v0.2.0
**阶段**: Phase 2 - 后端开发
**进度**: 60%

## 进度总览

| 阶段 | 状态 | 进度 | 备注 |
|------|------|------|------|
| Phase 1 | ✅ 完成 | 100% | |
| Phase 2 | 🔄 进行中 | 60% | |
| Phase 3 | ⏳ 待开始 | 0% | |

## 详细进度

### Phase 1: 阶段名称 ✅
- [x] 任务 1
- [x] 任务 2

### Phase 2: 阶段名称 🔄
- [x] 任务 3
- [ ] 任务 4（进行中）
- [ ] 任务 5

## 阻塞项
- 无 / 阻塞项描述

## 下一步
- 下一步计划
```

### 4.3 状态标记

| 标记 | 含义   | 使用场景       |
| ---- | ------ | -------------- |
| ✅   | 已完成 | 任务/阶段完成  |
| 🔄   | 进行中 | 当前正在进行   |
| ⏳   | 待开始 | 尚未开始       |
| ❌   | 已取消 | 任务被取消     |
| ⚠️   | 有风险 | 存在风险或延期 |

## 五、变更记录 (changes.md)

### 5.1 文档定位

变更记录记录重要的设计变更、决策和原因。**记录"为什么变"比"变了什么"更重要。**

### 5.2 必须包含的章节

```
# 变更记录

## [日期] 变更标题

**变更类型**: 设计变更 / 需求变更 / 技术决策

**影响范围**: 模块名称

**变更内容**:
- 变更前：xxx
- 变更后：xxx

**变更原因**:
- 原因说明

**影响评估**:
- 影响的模块
- 需要修改的文档
- 需要修改的代码

**决策人**: xxx

---
```

### 5.3 变更类型

| 类型     | 说明                           | 示例                    |
| -------- | ------------------------------ | ----------------------- |
| 设计变更 | 架构、数据模型、接口等设计变更 | 数据库表结构调整        |
| 需求变更 | 功能需求、业务规则变更         | 新增功能、修改业务逻辑  |
| 技术决策 | 技术选型、实现方案决策         | 选择 Tailscale 替代 FRP |
| 废弃声明 | 废弃某个功能或接口             | 废弃旧版 API            |

## 六、images 目录规范

### 6.1 目录位置

`/images/` 目录与 `/docs/` 目录同级，存放所有设计图。

### 6.2 命名规范

| 图片类型   | 命名格式                        | 示例                                 |

## 七、文档审查清单

创建或修改文档时，请检查以下项目：

| 检查项                    | 说明                            |
| ------------------------- | ------------------------------- |
| [ ] 文件命名符合规范      | `design_<module>.md` 格式       |
| [ ] 章节结构完整          | 包含所有必须章节                |
| [ ] 无代码片段            | 无 Go/JS/SQL/配置文件代码       |
| [ ] 流程图使用 txt 格式   | 使用字符绘制                    |
| [ ] 界面设计有 txt 线框图 | 描述基本布局                    |
| [ ] 复杂设计有配套 SVG 图 | 存放在 /images/                 |
| [ ] SVG 图命名符合规范    | `design_<module>_<feature>.svg` |
| [ ] 表格格式正确          | 使用 Markdown 表格              |
| [ ] 图片链接有效          | `../images/xxx.svg`             |
