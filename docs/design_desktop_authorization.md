# 桌面授权系统设计

## 1. 概述

### 1.1 模块职责

桌面授权系统负责管理 Desktop 客户端对 Agent 服务的访问权限，支持按客户端和按分组两种授权方式。

### 1.2 核心功能

- 服务基础权限管理（public/private/group）
- 额外授权管理（按客户端授权、按分组授权）
- 授权有效期管理（永久/指定时间）
- ACL 规则自动同步

### 1.3 与其他模块的关系

| 模块          | 关系                                      |
| ------------- | ----------------------------------------- |
| Headscale ACL | 授权变更时同步 ACL 规则，实现网络层隔离   |
| 服务管理      | 授权基于 ProxyService 进行                |
| 客户端管理    | 按客户端授权时关联 Client/DesktopInstance |
| 分组管理      | 按分组授权时关联 Group                    |

### 1.4 网段说明

#### 理想设计（未实现）

根据安全架构设计（详见 design_tailscale_security.md），理想的网段规划如下：

| 网段          | 用途              | 说明              |
| ------------- | ----------------- | ----------------- |
| 100.64.0.0/16 | Agent（服务端）   | 固定 IP，提供服务 |
| 100.65.0.0/16 | Desktop（客户端） | 固定 IP，访问服务 |
| 100.66.0.0/16 | Server（管理端）  | 预留              |

#### 实际实现

由于 Headscale 不支持按 User 分配不同网段，实际所有节点共用同一网段：

| 网段          | 用途                 | 说明              |
| ------------- | -------------------- | ----------------- |
| 100.64.0.0/10 | Agent + Desktop 共用 | 按注册顺序分配 IP |

**限制说明**：

- Headscale 配置 `prefixes.v4: 100.64.0.0/10`，所有节点从此网段顺序分配
- 无法通过网段区分 Agent 和 Desktop，需通过 ACL 规则和数据库记录区分
- Agent 和 Desktop 的 IP 可能交错分布（如 Agent: 100.64.0.1, Desktop: 100.64.6.4）

**权限隔离方式**：

- 通过 Headscale ACL 规则控制访问权限
- 通过数据库记录区分节点类型
- 通过 Headscale User 区分（Agent 用 `agent-xxx`，Desktop 用 `desktop-xxx`）

## 3. 数据模型

### 3.1 ServicePermission 表（扩展）

| 字段       | 类型     | 必填 | 说明                                     |
| ---------- | -------- | ---- | ---------------------------------------- |
| id         | int64    | 是   | 主键，自增                               |
| service_id | int64    | 是   | 服务 ID，外键关联 proxy_services         |
| perm_type  | string   | 是   | 授权类型：client / group                 |
| client_id  | int64    | 否   | 被授权的客户端 ID（perm_type=client 时） |
| group_id   | int64    | 否   | 被授权的分组 ID（perm_type=group 时）    |
| granted_by | int64    | 是   | 授权人（Admin ID）                       |
| granted_at | datetime | 是   | 授权时间                                 |
| expires_at | datetime | 否   | 过期时间（null 表示永久）                |
| created_at | datetime | 是   | 创建时间                                 |

### 3.2 字段约束

| 约束               | 说明                                         |
| ------------------ | -------------------------------------------- |
| perm_type 枚举     | 只能是 client 或 group                       |
| client_id 条件必填 | perm_type=client 时必填                      |
| group_id 条件必填  | perm_type=group 时必填                       |
| 唯一约束           | (service_id, perm_type, client_id, group_id) |

### 3.3 关联关系

```txt
┌─────────────────────────────────────────────────────────────────────────────┐
│                          数据关联关系                                        │
```

### 4.2 ACL 规则生成逻辑

| 授权类型 | ACL 规则生成                                                |
| -------- | ----------------------------------------------------------- |
| 按客户端 | src: [client.tailscale_ip], dst: [agent.ts_ip:service.port] |
| 按分组   | 遍历分组成员，为每个成员生成独立规则                        |

### 4.3 异常处理

| 异常场景              | 处理方式                        |
| --------------------- | ------------------------------- |
| 服务不存在            | 返回 404 错误                   |
| 客户端/分组不存在     | 返回 404 错误                   |
| 授权已存在            | 返回 409 冲突错误               |
| ACL 同步失败          | 回滚授权记录，返回 500 错误     |
| 客户端无 Tailscale IP | 返回 400 错误，提示客户端未连接 |

## 5. 接口设计

### 5.1 API 列表

| 方法   | 路径                                        | 说明             |
| ------ | ------------------------------------------- | ---------------- |
| GET    | /api/v1/admin/services/permissions          | 获取所有服务权限 |
| GET    | /api/v1/admin/services/:id/permissions      | 获取服务权限列表 |
| POST   | /api/v1/admin/services/:id/permissions      | 添加服务权限     |
| DELETE | /api/v1/admin/services/:id/permissions/:pid | 删除服务权限     |

### 5.2 添加服务权限请求

| 字段       | 类型   | 必填 | 说明                                 |
| ---------- | ------ | ---- | ------------------------------------ |
| perm_type  | string | 是   | 授权类型：client / group             |
| client_id  | int64  | 条件 | 客户端 ID（perm_type=client 时必填） |
| group_id   | int64  | 条件 | 分组 ID（perm_type=group 时必填）    |
| expires_at | string | 否   | 过期时间（RFC3339 格式）             |

### 5.3 服务权限响应

| 字段         | 类型     | 说明                        |
| ------------ | -------- | --------------------------- |
| id           | int64    | 权限 ID                     |
| service_id   | int64    | 服务 ID                     |
| service_name | string   | 服务名称                    |
| perm_type    | string   | 授权类型                    |
| client_id    | int64    | 客户端 ID（按客户端授权时） |
| client_name  | string   | 客户端名称                  |
| group_id     | int64    | 分组 ID（按分组授权时）     |
| group_name   | string   | 分组名称                    |
| granted_by   | int64    | 授权人 ID                   |
| granted_at   | datetime | 授权时间                    |
| expires_at   | datetime | 过期时间                    |

### 5.4 错误码定义

| 错误码 | 说明                   |
| ------ | ---------------------- |
| 400    | 请求参数错误           |
| 404    | 服务/客户端/分组不存在 |
| 409    | 授权已存在             |
| 500    | 服务器内部错误         |

## 7. 安全设计

### 7.1 权限控制

| 操作         | 权限要求 |
| ------------ | -------- |
| 查看授权列表 | 管理员   |
| 添加授权     | 管理员   |
| 删除授权     | 管理员   |
| 修改服务权限 | 管理员   |

### 7.2 ACL 同步安全

| 安全措施   | 说明                            |
| ---------- | ------------------------------- |
| 事务一致性 | 授权记录和 ACL 同步在同一事务中 |
| 失败回滚   | ACL 同步失败时回滚授权记录      |
| 审计日志   | 记录所有授权变更操作            |

### 7.3 过期授权处理

| 处理方式 | 说明                                   |
| -------- | -------------------------------------- |
| 定时任务 | 每小时检查过期授权，自动删除并同步 ACL |
| 实时检查 | 访问时检查授权是否过期                 |
