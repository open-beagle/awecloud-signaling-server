### Token 生命周期

```
┌─────────────────────────────────────────────────────────────────┐
│                      Token 状态流转                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────┐   24小时内首次部署   ┌─────────┐                   │
│  │ pending │ ──────────────────▶ │  bound  │                   │
│  │ 待使用  │                      │ 已绑定  │                   │
│  └────┬────┘                      └────┬────┘                   │
│       │                                │                        │
│       │ 24小时未使用                   │ 同设备可重复使用       │
│       ▼                                │ (升级/重装)            │
│  ┌─────────┐                           │                        │
│  │ expired │                           ▼                        │
│  │  过期   │                      永久有效                      │
│  └─────────┘                      绑定设备指纹                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### Token 使用规则

| 场景                   | Token 状态 | 结果                                 |
| ---------------------- | ---------- | ------------------------------------ |
| 首次部署（24小时内）   | pending    | 成功，Token 变为 bound，绑定设备指纹 |
| 首次部署（超过24小时） | expired    | 失败，需重新生成 Token               |
| 同设备升级/重装        | bound      | 成功，验证设备指纹匹配               |
| 其他设备使用           | bound      | 失败，设备指纹不匹配                 |
| 新增设备               | -          | 需重新生成新 Token                   |

### API 设计

```
# 生成部署 Token
POST /api/v1/agent/:agent_id/deploy-token
请求:
{
  "device_name": "beagle-node-01"  // 必填
}

响应:
{
  "success": true,
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires_at": "2026-02-03T10:30:00Z",
  "install_command": "curl -fsSL https://... | sudo bash -s -- ..."
}

# 查询部署 Token 历史
GET /api/v1/agent/:agent_id/deploy-tokens?page=1&page_size=20

# Agent 安装时验证 Token
POST /api/v1/agent/register
请求:
{
  "token": "...",
  "device_fingerprint": "abc123..."
}

响应（首次部署）:
{
  "success": true,
  "message": "部署成功，Token 已绑定设备",
  "config": { ... }
}

响应（同设备升级）:
{
  "success": true,
  "message": "升级成功",
  "config": { ... }
}

响应（设备不匹配）:
{
  "success": false,
  "message": "Token 已绑定其他设备，请生成新 Token"
}
```

### 数据模型

```
表名: agent_deploy_tokens

字段:
- id: 主键
- token: 部署 Token（加密存储）
- agent_id: 关联的 Agent ID
- device_name: 设备名称（必填）
- status: pending | bound | expired
- device_fingerprint: 绑定的设备指纹（首次部署后填充）
- created_by: 创建人（管理员 ID）
- created_at: 创建时间
- expires_at: 首次部署截止时间（24小时）
- bound_at: 绑定时间（首次部署成功时更新）
- last_used_at: 最后使用时间
- node_id: 关联的 Node ID
```

### Agent 命令行参数（cmd/agent/main.go）

Agent 需要支持部署模式，通过命令行参数接收部署信息：

| 参数 | 说明                        | 示例                           |
| ---- | --------------------------- | ------------------------------ |

| -s   | Server 地址（部署模式必填） | -s https://signal.wodcloud.com |

```
┌─────────────────────────────────────────────────────────────────┐
│                         登录                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Server 地址:  [https://signal.wodcloud.com    ]               │
```

### 接口设计

#### gRPC 接口（Desktop 与 Server）

```
service DesktopService {
  // 发起登录，返回登录 URL，然后流式推送登录结果
  rpc Login(LoginRequest) returns (stream LoginResponse);
}

LoginRequest:
- device_fingerprint: 设备指纹
- device_name: 设备名称
- username: 用户名（可选，用于预填）

LoginResponse:
- 第一条消息: session_id + login_url（Desktop 打开浏览器）
- 第二条消息: 登录结果（成功时包含 token 和用户信息）
```

#### HTTP 接口（浏览器访问）

```
# 浏览器访问登录页面（重定向到 Logto）
GET /auth/desktop/:session_id
-> 302 重定向到 Logto 授权页面

# Logto 回调
GET /auth/desktop/callback?code=xxx&state=session_id
-> 验证 code，获取用户信息
-> 通过 gRPC 流推送结果给 Desktop
-> 显示"登录成功，可关闭此页面"
```

### 数据模型

```
表名: desktop_login_sessions

字段:
- id: 主键
- session_id: 会话 ID（UUID）
- device_fingerprint: 设备指纹
- device_name: 设备名称
- username_hint: 预填用户名
- status: pending | completed | expired | failed
- user_id: 登录成功后关联的用户 ID
- token: 生成的访问 Token
- created_at: 创建时间
- expires_at: 过期时间
- completed_at: 完成时间
```

### 方案优势

1. Desktop 不需要集成 Logto SDK，降低复杂度
2. Server 统一管理认证逻辑，便于扩展其他登录方式
3. 浏览器登录体验更好（支持密码管理器、已登录状态等）
4. 安全性更高，Token 由 Server 签发和管理
5. gRPC 流式推送，实时获取登录结果，无需轮询

## 三、Client Token 与 CloudIDE 集成

### 核心思路

Desktop 通过网页登录后，用户已有身份认证。类似 Agent 部署流程，用户可以生成 `client.token` 给 CloudIDE、kubectl ts 等客户端使用。

### API 设计

```
# Server 生成 Client Token（CloudIDE 服务调用，需要服务认证）
POST /api/v1/client/token
请求:
{
  "user_id": "userA",
  "device_name": "cloudide-project-abc"
}

响应:
{
  "success": true,
  "token": "ct_eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "device_name": "cloudide-project-abc",
  "created_at": "2026-02-02T10:30:00Z"
}

# 查询用户的 Client Token 列表（管理接口）
GET /api/v1/client/tokens?user_id=userA

# 删除 Client Token
DELETE /api/v1/client/token/:id

# CloudIDE 注册（使用 client.token）
POST /api/v1/client/register
请求:
{
  "token": "ct_eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "device_fingerprint": "fp_xxx..."
}

响应:
{
  "success": true,
  "auth_key": "tskey-auth-xxx...",
  "headscale_url": "https://headscale.wodcloud.com",
  "user": "userA"
}
```

### 数据模型

```
表名: client_tokens

字段:
- id: 主键
- token: Client Token（加密存储，前缀 ct_）
- user_id: 关联的用户 ID
- name: Token 名称
- status: pending | bound
- device_fingerprint: 绑定的设备指纹（首次使用后填充）
- device_name: 设备名称（首次使用后填充）
- created_at: 创建时间
- bound_at: 绑定时间
- last_used_at: 最后使用时间
- node_id: 关联的 Headscale Node ID
```

### CloudIDE 容器配置

```yaml
# Kubernetes Pod 环境变量
env:
  - name: CLIENT_TOKEN
    valueFrom:
      secretKeyRef:
        name: cloudide-client-token
        key: token
  - name: SERVER_ADDRESS
    value: "https://signal.wodcloud.com"
  - name: DEVICE_NAME
    value: "cloudide-project-abc"
  - name: USER_ID
    value: "userA" # 关联的用户 ID，从 Logto 获取
```

注意：USER_ID 需要与 Logto 用户体系关联，CloudIDE 创建时从用户登录信息获取。

### 与 Agent Token 的对比

| 特性         | Agent Token      | Client Token              |
| ------------ | ---------------- | ------------------------- |
| 生成者       | 管理员           | 管理员（Server API）      |
| 用途         | 部署 Agent       | CloudIDE/kubectl 等客户端 |
| 首次使用时限 | 24小时           | 无限制                    |
| 绑定设备     | 是               | 是                        |
| 关联账户     | agent-xxx        | 用户账户                  |
| 权限         | Agent 服务提供者 | 继承用户权限              |

### kubectl ts 插件使用示例

```
用法：
1. 管理员在 Server 为用户生成 Client Token
2. 用户在本地执行: kubectl ts login --token ct_xxx... --server https://signal.wodcloud.com
3. 插件使用 token 注册，获取 auth_key
4. 启动本地 Tailscale，以用户身份加入网络
5. 用户可以访问 K8s API Server（如果 ACL 允许）
```

### 设计决策

1. **节点清理**：CloudIDE 容器重启时保持 IP 不变，节点只能通过 Server 设备管理页面手动删除
2. **多实例命名**：部署时必须指定名称（device_name 参数）
