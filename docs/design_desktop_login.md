# Desktop 登录设计

> 本文档描述 Desktop 客户端的登录设计，基于 Logto + 钉钉实现用户 SSO 登录，并自动完成设备注册。

## 1. 设计概述

### 1.2 与现有登录的对比

| 对比项   | 现有方式            | 新方式（Logto）             |
| -------- | ------------------- | --------------------------- |
| 认证方式 | Client ID + Secret  | 钉钉扫码                    |
| 用户管理 | 手动创建 Client     | 自动同步 Logto 用户         |
| 设备注册 | 登录时自动注册      | 登录时自动注册（不变）      |
| 凭据存储 | desktop_id + secret | desktop_id + secret（不变） |

## 3. 浏览器授权流程

### 3.1 打开浏览器

Desktop 点击登录后，打开系统默认浏览器：

| 参数                  | 说明                      |
| --------------------- | ------------------------- |
| 授权 URL              | Logto /oidc/auth          |
| response_type         | code                      |
| client_id             | signaling-desktop 应用 ID |
| redirect_uri          | signaling://callback      |
| scope                 | openid profile email      |
| state                 | 随机字符串                |
| code_challenge        | PKCE 挑战码               |
| code_challenge_method | S256                      |

### 3.2 自定义协议处理

Desktop 注册自定义协议 `signaling://` 处理回调：

| 平台    | 注册方式                    |
| ------- | --------------------------- |
| Windows | 注册表 HKEY_CLASSES_ROOT    |
| macOS   | Info.plist CFBundleURLTypes |
| Linux   | .desktop 文件 MimeType      |

### 3.3 回调处理

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                                    回调处理流程                                          │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  1. 浏览器重定向到 signaling://callback?code=xxx&state=xxx                              │
│                                                                                         │
│  2. 系统唤起 Desktop 应用                                                               │
│                                                                                         │
│  3. Desktop 解析 URL 参数                                                               │
│     - 验证 state 与发起时一致                                                           │
│     - 提取 authorization_code                                                           │
│                                                                                         │
│  4. 使用 code 换取 Token                                                                │
│     - POST Logto /oidc/token                                                            │
│     - 携带 code, client_id, redirect_uri, code_verifier                                │
│                                                                                         │
│  5. 获取 id_token 和 access_token                                                       │
│                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

## 4. Server gRPC 登录

### 4.1 用户管理策略

采用"预创建用户"策略，管理员需先在 Server 创建 User，用户才能登录：

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                                  预创建用户流程                                          │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  阶段 1：管理员创建用户                                                                 │
│  ┌─────────────────────────────────────────────────────────────────────────────────┐   │
│  │  1. 管理员登录 Server Web                                                        │   │
│  │  2. 进入用户管理页面                                                             │   │
│  │  3. 创建新用户，填写：                                                           │   │
│  │     - name: 用户名                                                               │   │
│  │     - phone: 手机号（必须与钉钉绑定手机号一致）                                  │   │
│  │     - alias: 别名（可选）                                                        │   │
│  │  4. 用户创建成功，role = client                                                  │   │
│  └─────────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                         │
│  阶段 2：用户登录                                                                       │
│  ┌─────────────────────────────────────────────────────────────────────────────────┐   │
│  │  1. 用户打开 Desktop，点击钉钉登录                                               │   │
│  │  2. 钉钉扫码授权                                                                 │   │
│  │  3. Server 根据 phone 查询 user 表                                               │   │
│  │     - 找到 → 登录成功，更新 logto_id                                             │   │
│  │     - 未找到 → 返回错误"用户未授权，请联系管理员开通权限"                         │   │
│  └─────────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 新增 RPC 接口

| 接口           | 说明                     |
| -------------- | ------------------------ |
| LoginWithLogto | 使用 Logto id_token 登录 |

### 4.3 LoginWithLogto 请求

| 字段               | 类型              | 说明                  |
| ------------------ | ----------------- | --------------------- |
| id_token           | string            | Logto 签发的 id_token |
| server_address     | string            | 服务器地址            |
| device_name        | string            | 设备名称              |
| device_fingerprint | string            | 设备指纹              |
| system_info        | DesktopSystemInfo | 系统信息              |

### 4.4 LoginWithLogto 响应

| 字段       | 类型                | 说明                 |
| ---------- | ------------------- | -------------------- |
| success    | bool                | 是否成功             |
| message    | string              | 响应消息             |
| desktop_id | uint64              | Desktop Node ID      |
| secret     | string              | Desktop 专属密钥     |
| auth_key   | string              | Tailscale PreAuthKey |
| server_url | string              | Headscale 服务器地址 |
| services   | []AuthorizedService | 已授权服务列表       |
| devices    | []DesktopDevice     | 我的设备列表         |

### 4.5 Server 端处理流程

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                              LoginWithLogto 处理流程                                     │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  1. 验证 id_token                                                                       │
│     ┌─────────────────────────────────────────────────────────────────────────────┐    │
│     │  - 获取 Logto JWKS 公钥                                                      │    │
│     │  - 验证签名                                                                  │    │
│     │  - 验证 iss（签发者）                                                        │    │
│     │  - 验证 aud（受众）= signaling-desktop                                       │    │
│     │  - 验证 exp（过期时间）                                                      │    │
│     └─────────────────────────────────────────────────────────────────────────────┘    │
│                                                                                         │
│  2. 提取用户信息（钉钉三件套）                                                          │
│     ┌─────────────────────────────────────────────────────────────────────────────┐    │
│     │  - unionid: 钉钉用户唯一标识（钉钉号）                                       │    │
│     │  - mobile: 手机号                                                            │    │
│     │  - nick: 昵称（用户中文姓名）                                                │    │
│     └─────────────────────────────────────────────────────────────────────────────┘    │
│                                                                                         │
│  3. 按 phone 查询 User（预创建用户策略）                                                │
│     ┌─────────────────────────────────────────────────────────────────────────────┐    │
│     │  - 根据 mobile 查询 user 表的 phone 字段                                     │    │
│     │  - 未找到 → 返回错误"用户未授权，请联系管理员开通权限"                        │    │
│     │  - 找到 → 更新 dingtalk_id, name（如有变化）                                 │    │
│     │  - 验证 role = client                                                        │    │
│     └─────────────────────────────────────────────────────────────────────────────┘    │
│                                                                                         │
│  4. 查询或创建 Node（设备）                                                             │
│     ┌─────────────────────────────────────────────────────────────────────────────┐    │
│     │  - 根据 user_id + device_fingerprint 查询 node 表                            │    │
│     │  - 不存在则创建新设备                                                        │    │
│     │  - 存在则更新 device_name, system_info                                       │    │
│     │  - 生成新的 desktop_secret                                                   │    │
│     └─────────────────────────────────────────────────────────────────────────────┘    │
│                                                                                         │
│  5. 创建 Tailscale PreAuthKey                                                           │
│     ┌─────────────────────────────────────────────────────────────────────────────┐    │
│     │  - 调用 Headscale API 创建预认证密钥                                         │    │
│     │  - 设置 Tags: tag:client-{username}                                          │    │
│     │  - 有效期 24 小时                                                            │    │
│     └─────────────────────────────────────────────────────────────────────────────┘    │
│                                                                                         │
│  6. 查询已授权服务和设备列表                                                            │
│                                                                                         │
│  7. 返回响应                                                                            │
│                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

### 6.3 自动登录流程

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                                    自动登录流程                                          │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  1. 检查本地凭据                                                                        │
```

## 8. 错误处理

| 错误场景          | 处理方式                               |
| ----------------- | -------------------------------------- |
| 浏览器未打开      | 提示手动打开链接                       |
| 用户取消授权      | 返回登录页                             |
| state 不匹配      | 提示安全错误，重新登录                 |
| Token 换取失败    | 显示错误信息，重新登录                 |
| id_token 验证失败 | 提示认证失败，重新登录                 |
| 用户未授权        | 提示"用户未授权，请联系管理员开通权限" |
| Server 连接失败   | 提示网络错误，检查服务器地址           |
| 设备注册失败      | 显示错误信息，联系管理员               |

## 9. 兼容性设计

### 9.1 过渡期支持

在过渡期同时支持两种登录方式：

| 登录方式           | 说明               |
| ------------------ | ------------------ |
| Client ID + Secret | 现有方式，逐步废弃 |
| 钉钉扫码           | 新方式，推荐使用   |

### 9.2 迁移策略

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                                    迁移策略                                              │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  阶段 1：双模式并存                                                                     │
│  - 登录页同时显示两种登录方式                                                           │
│  - 现有用户可继续使用 Client ID + Secret                                                │
│  - 新用户推荐使用钉钉登录                                                               │
│                                                                                         │
│  阶段 2：关联账号                                                                       │
│  - 现有 Client 用户可关联 Logto 账号                                                    │
│  - 关联后可使用钉钉登录                                                                 │
│                                                                                         │
│  阶段 3：废弃旧方式                                                                     │
│  - 移除 Client ID + Secret 登录                                                         │
│  - 所有用户使用钉钉登录                                                                 │
│                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```
