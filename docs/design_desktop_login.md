# Desktop 登录流程设计

## 一、角色

| 角色            | 说明                                           |
| --------------- | ---------------------------------------------- |
| Desktop（前端） | Wails Vue 前端，用户交互界面                   |
| Desktop（Go）   | Wails Go 后端，负责 gRPC 通信                  |
| Server（gRPC）  | 信令服务器 gRPC 服务，登录会话创建和结果推送   |
| Server（HTTPS） | 信令服务器 Web 页面，承载 Logto OAuth 登录流程 |

Logto 由 Server（HTTPS）内部对接，Desktop 不直接与 Logto 交互。

## 二、首次登录流程

```
  Desktop（前端）          Desktop（Go）          Server（gRPC）         Server（HTTPS）
       │                       │                       │                       │
       │ 1.点击登录            │                       │                       │
       │──────────────────────>│                       │                       │
       │                       │                       │                       │
       │                       │ 2.gRPC: CreateLoginSession                   │
       │                       │   (server_addr, username_hint, device_info)   │
       │                       │──────────────────────>│                       │
       │                       │                       │                       │
       │                       │ 3.返回 {session_id, login_url}               │
       │                       │<──────────────────────│                       │
       │                       │                       │                       │
       │  ┌────────────────────────────────────────────────────────────────┐   │
       │  │                    并行执行                                    │   │
       │  ├────────────────────────────────────────────────────────────────┤   │
       │  │                                                                │   │
       │  │  路径A: gRPC 侦听登录结果                                      │   │
       │  │                                                                │   │
       │  │      Desktop（Go）          Server（gRPC）                     │   │
       │  │           │                       │                            │   │
       │  │           │ 4.gRPC: WaitForLoginResult                        │   │
       │  │           │   (session_id)        │                            │   │
       │  │           │──────────────────────>│                            │   │
       │  │           │                       │                            │   │
       │  │           │   (持续侦听，5分钟超时)                            │   │
       │  │           │                       │                            │   │
       │  │                                                                │   │
       │  │  路径B: WebView 登录                                           │   │
       │  │                                                                │   │
       │  │  Desktop（前端）                              Server（HTTPS）  │   │
       │  │       │                                            │           │   │
       │  │       │ 5.打开 WebView 窗口                        │           │   │
       │  │       │   URL = login_url                          │           │   │
       │  │       │                                            │           │   │
       │  │       │ 6.WebView 加载登录页面                     │           │   │
       │  │       │───────────────────────────────────────────>│           │   │
       │  │       │                                            │           │   │
       │  │       │                                  7.重定向到 Logto      │   │
       │  │       │<───────────────────────────────────────────│           │   │
       │  │       │                                            │           │   │
       │  │       │ 8.用户完成登录（钉钉扫码/密码/SSO）       │           │   │
       │  │       │                                            │           │   │
       │  │       │ 9.Logto 回调到 Server                      │           │   │
       │  │       │───────────────────────────────────────────>│           │   │
       │  │       │                                            │           │   │
       │  │       │                                  10.验证 token         │   │
       │  │       │                                     查找/创建 User     │   │
       │  │       │                                     更新会话状态       │   │
       │  │       │                                     通知结果通道 ──────────>│
       │  │       │                                            │           │   │
       │  │       │ 11.WebView 显示"登录成功"                  │           │   │
       │  │       │<───────────────────────────────────────────│           │   │
       │  │       │                                            │           │   │
       │  └────────────────────────────────────────────────────────────────┘   │
       │                       │                       │                       │
       │                       │ 12.侦听返回登录成功   │                       │
       │                       │   {desktop_id, device_token,                  │
       │                       │    auth_key, username}│                       │
       │                       │<──────────────────────│                       │
       │                       │                       │                       │
       │                       │ 13.关闭 WebView 窗口  │                       │
       │                       │                       │                       │
       │                       │ 14.保存凭据到本地     │                       │
       │                       │    启动心跳流         │                       │
       │                       │                       │                       │
       │ 15.登录成功           │                       │                       │
       │<──────────────────────│                       │                       │
       │                       │                       │                       │
       │ 16.进入"我的服务"页面 │                       │                       │
       │                       │                       │                       │
```

四步概括：

1. gRPC 创建 Session，拿到 session_id 和 login_url
2. gRPC 侦听 session_id 的登录结果（与步骤 3 并行，5 分钟超时）
3. WebView 打开 login_url，用户在 Server 网页完成登录，Server 内部通知结果通道
4. 侦听返回成功，拿到凭证，关闭登录页，进入"我的服务"

## 三、自动登录流程

```
  Desktop（前端）          Desktop（Go）          Server（gRPC）
       │                       │                       │
       │ 1.启动，检查本地凭据  │                       │
       │──────────────────────>│                       │
       │                       │                       │
       │ 2.有凭据，显示自动登录界面（旋转动画）        │
       │<──────────────────────│                       │
       │                       │                       │
       │                       │ 3.gRPC: Authenticate  │
       │                       │   (desktop_id, secret)│
       │                       │──────────────────────>│
       │                       │                       │
       │                       │ 4.认证成功            │
       │                       │   返回 auth_key       │
       │                       │<──────────────────────│
       │                       │                       │
       │                       │ 5.启动心跳流          │
       │                       │                       │
       │ 6.进入"我的服务"页面  │                       │
       │<──────────────────────│                       │
       │                       │                       │
```

认证失败时清除本地凭据，切换到首次登录流程。

## 四、gRPC API

| 方法                  | 类型   | 说明                                       |
| --------------------- | ------ | ------------------------------------------ |
| CreateLoginSession    | Unary  | 创建登录会话，返回 session_id 和 login_url |
| WaitForLoginResult    | 双向流 | 侦听登录结果，5 分钟超时                   |
| Authenticate          | Unary  | 使用 desktop_id + secret 认证              |
| Heartbeat             | 双向流 | 心跳保活，同步已授权服务列表               |
| CheckSavedCredentials | Unary  | 检查是否有保存的凭据                       |

## 五、HTTPS 端点

| 端点                       | 说明                      |
| -------------------------- | ------------------------- |
| /auth/desktop/{session_id} | 302 重定向到 Logto 登录页 |
| /auth/desktop/callback     | Logto 回调，处理登录结果  |

仅供 WebView 访问，Desktop 不直接调用。

## 六、登录会话

会话存储在数据库，字段：session_id、device_name、device_fingerprint、username_hint、status（pending/completed/failed/expired）、user_id、error_message、expires_at、created_at。

内存中维护两个映射：

- 登录结果通道：HTTPS 回调完成后通知 gRPC 侦听流
- Logto SDK 会话存储：维护 OAuth 状态（PKCE、state 等）

## 七、错误处理

| 场景            | 处理                             |
| --------------- | -------------------------------- |
| 会话不存在/过期 | WebView 显示错误页面             |
| Logto 认证失败  | WebView 显示错误，通知侦听流失败 |
| 侦听超时        | 前端提示"登录超时，请重试"       |
| 自动登录失败    | 清除凭据，切换到首次登录         |
