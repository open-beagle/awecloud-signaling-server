# 登录系统设计

> 本文档描述 AWECloud Signaling 系统的统一登录设计，基于 Logto + 钉钉实现 SSO 单点登录。

## 1. 设计概述

### 1.1 登录架构

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                                    登录架构总览                                          │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  ┌─────────────┐         ┌─────────────┐         ┌─────────────┐                       │
│  │   Server    │         │    Logto    │         │    钉钉     │                       │
│  │   Web 端    │────────►│   (IdP)     │────────►│   扫码      │                       │
│  └─────────────┘         └─────────────┘         └─────────────┘                       │
│        │                       │                                                        │
│        │                       │ OIDC                                                   │
│        │◄──────────────────────┘                                                        │
│        │  id_token + access_token                                                       │
│        │                                                                                │
│        ▼                                                                                │
│  ┌─────────────┐                                                                        │
│  │   Admin     │                                                                        │
│  │   身份      │                                                                        │
│  └─────────────┘                                                                        │
│                                                                                         │
│  ┌─────────────┐         ┌─────────────┐         ┌─────────────┐                       │
│  │   Desktop   │         │   浏览器    │         │    Logto    │                       │
│  │   客户端    │────────►│   跳转      │────────►│   钉钉扫码  │                       │
│  └─────────────┘         └─────────────┘         └─────────────┘                       │
│        │                       │                                                        │
│        │◄──────────────────────┘ 回调                                                   │
│        │  authorization_code                                                            │
│        │                                                                                │
│        ▼                                                                                │
│  ┌─────────────┐         ┌─────────────┐                                               │
│  │   Server    │────────►│   User      │                                               │
│  │   gRPC      │         │   身份      │                                               │
│  └─────────────┘         │ + 设备注册  │                                               │
│                          └─────────────┘                                               │
│                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

### 1.2 角色说明

| 角色  | 登录入口       | 身份来源       | 权限范围                   |
| ----- | -------------- | -------------- | -------------------------- |
| Admin | Server Web     | Logto 管理员   | 管理用户、设备、服务、授权 |
| User  | Desktop 客户端 | Logto 普通用户 | 访问已授权的服务           |

### 1.3 技术选型

| 组件  | 技术  | 说明                      |
| ----- | ----- | ------------------------- |
| IdP   | Logto | 开源身份提供商，支持 OIDC |
| SSO   | 钉钉  | 企业级扫码登录            |
| 协议  | OIDC  | OpenID Connect 标准协议   |
| Token | JWT   | id_token 和 access_token  |

## 2. Logto 配置

### 2.1 应用配置

需要在 Logto 中创建两个应用：

| 应用名称          | 类型            | 用途                  |
| ----------------- | --------------- | --------------------- |
| signaling-web     | Traditional Web | Server Web 管理端登录 |
| signaling-desktop | Native App      | Desktop 客户端登录    |

### 2.2 signaling-web 应用配置

| 配置项               | 值                                  |
| -------------------- | ----------------------------------- |
| Application Type     | Traditional Web                     |
| Redirect URIs        | https://server.example.com/callback |
| Post Logout URIs     | https://server.example.com/login    |
| CORS Allowed Origins | https://server.example.com          |

### 2.3 signaling-desktop 应用配置

| 配置项           | 值                   |
| ---------------- | -------------------- |
| Application Type | Native App           |
| Redirect URIs    | signaling://callback |
| Post Logout URIs | signaling://logout   |

### 2.4 钉钉社交连接器配置

在 Logto 中配置钉钉社交连接器：

| 配置项     | 说明                 |
| ---------- | -------------------- |
| App ID     | 钉钉开放平台应用 ID  |
| App Secret | 钉钉开放平台应用密钥 |
| Scope      | openid, profile      |

## 3. 用户同步

### 3.1 同步策略

采用"预创建用户"策略，管理员需先在 Server 创建 User，用户才能通过钉钉登录：

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                                  预创建用户策略                                          │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  ┌─────────────┐    创建用户    ┌─────────────┐                                        │
│  │   Admin     │───────────────►│   user 表   │                                        │
│  │   管理员    │                │             │                                        │
│  │             │                │  name       │                                        │
│  │             │                │  phone ◄────┼──── 必须与钉钉绑定手机号一致            │
│  │             │                │  role       │                                        │
│  └─────────────┘                └─────────────┘                                        │
│                                       │                                                 │
│                                       │ 用户登录时                                      │
│                                       ▼                                                 │
│  ┌─────────────┐    钉钉登录    ┌─────────────┐    按 phone   ┌─────────────┐         │
│  │   Desktop   │───────────────►│   Logto     │───────────────►│   Server    │         │
│  │   用户      │                │   钉钉      │    查询        │             │         │
│  │             │                │             │                │  找到 → 登录│         │
│  │             │                │  mobile     │                │  未找到→拒绝│         │
│  └─────────────┘                └─────────────┘                └─────────────┘         │
│                                                                                         │
│  钉钉返回字段：                                                                         │
│  - unionid: 钉钉用户唯一标识（钉钉号）                                                  │
│  - mobile: 手机号（用于匹配 user 表）                                                   │
│  - nick: 昵称（用户中文姓名）                                                           │
│                                                                                         │
│  优点：                                                                                 │
│  - 管理员可控，只有授权用户才能登录                                                     │
│  - 手机号是企业员工常用标识，便于管理                                                   │
│  - 避免未知用户自动注册                                                                 │
│                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 用户映射

| 钉钉字段 | user 表字段 | 说明                 |
| -------- | ----------- | -------------------- |
| unionid  | dingtalk_id | 钉钉用户唯一标识     |
| mobile   | phone       | 手机号（匹配字段）   |
| nick     | name        | 用户名               |
| -        | role        | 角色（admin/client） |
| -        | alias       | 别名（可自定义）     |

### 3.3 角色分配

| 登录入口   | 默认角色 | 说明                         |
| ---------- | -------- | ---------------------------- |
| Server Web | admin    | 管理员，可管理所有资源       |
| Desktop    | client   | 普通用户，只能访问已授权服务 |

## 4. Token 管理

### 4.1 Token 类型

| Token 类型    | 用途              | 有效期 |
| ------------- | ----------------- | ------ |
| id_token      | 用户身份信息      | 1 小时 |
| access_token  | API 访问凭证      | 1 小时 |
| refresh_token | 刷新 access_token | 14 天  |

### 4.2 Token 存储

| 端         | 存储位置            | 说明             |
| ---------- | ------------------- | ---------------- |
| Server Web | HttpOnly Cookie     | 安全存储，防 XSS |
| Desktop    | 系统密钥链/加密文件 | 本地安全存储     |

### 4.3 Token 刷新

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                                    Token 刷新流程                                        │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  1. access_token 过期前 5 分钟，自动触发刷新                                            │
│  2. 使用 refresh_token 向 Logto 请求新的 access_token                                   │
│  3. 如果 refresh_token 也过期，跳转重新登录                                             │
│                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

## 5. 安全设计

### 5.1 PKCE 流程

Desktop 客户端使用 PKCE（Proof Key for Code Exchange）增强安全性：

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                                    PKCE 流程                                             │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  1. Desktop 生成 code_verifier（随机字符串）                                            │
│  2. 计算 code_challenge = SHA256(code_verifier)                                         │
│  3. 授权请求携带 code_challenge                                                         │
│  4. Token 请求携带 code_verifier                                                        │
│  5. Logto 验证 SHA256(code_verifier) == code_challenge                                  │
│                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

### 5.2 State 参数

防止 CSRF 攻击：

| 参数  | 说明                           |
| ----- | ------------------------------ |
| state | 随机字符串，回调时验证一致性   |
| nonce | 防重放攻击，包含在 id_token 中 |
