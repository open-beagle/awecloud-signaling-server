# Headscale 集成设计

## 1. 概述

### 1.1 模块职责

本文档描述 Server 与 Headscale 的集成方式，包括数据对象映射、认证流程、数据同步机制。

### 1.2 核心概念

| Headscale 对象 | 说明                                 | ID 类型 |
| -------------- | ------------------------------------ | ------- |
| User           | 用户/命名空间，用于组织节点          | uint64  |
| Node           | 节点/机器，实际连接的设备            | uint64  |
| PreAuthKey     | 预认证密钥，用于节点注册的一次性凭证 | string  |
| Tag            | 标签，用于 ACL 分组                  | string  |
| ACL            | 访问控制列表                         | JSON    |

### 1.3 对象关系

| 关系        | 说明                           |
| ----------- | ------------------------------ |
| User : Node | 1 : N，一个 User 可有多个 Node |
| Node : IP   | 1 : 1，每个 Node 有唯一 IP     |
| Node : Tag  | N : M，节点可有多个标签        |

## 4. 数据存储设计

### 4.1 Server 需要存储的 Headscale 数据

| 字段         | 存储位置        | 来源               | 用途                   |
| ------------ | --------------- | ------------------ | ---------------------- |
| ts_user_id   | Agent/Client 表 | 创建 User 时返回   | 创建 PreAuthKey 时使用 |
| ts_user_name | Agent/Client 表 | 创建 User 时返回   | 显示、调试             |
| ts_node_id   | Agent/Client 表 | 查询 Node 列表获取 | 删除节点、更新 Tags    |
| ts_ip        | Agent/Client 表 | Agent/Desktop 上报 | ACL 规则生成           |

### 4.2 为什么需要存储这些数据

| 场景               | 需要的数据 | 说明                          |
| ------------------ | ---------- | ----------------------------- |
| 创建 PreAuthKey    | ts_user_id | API 要求传 User ID，不是 Name |
| 生成 ACL 规则      | ts_ip      | ACL 基于 IP 地址              |
| 删除 Agent/Desktop | ts_node_id | 需要调用 Headscale 删除 Node  |
| 更新节点 Tags      | ts_node_id | 需要指定 Node ID              |

## 5. Headscale API 使用说明

### 5.1 创建 User

| 项目 | 说明                                             |
| ---- | ------------------------------------------------ |
| 端点 | POST /api/v1/user                                |
| 请求 | { "name": "agent-xxx" }                          |
| 响应 | { "user": { "id": "123", "name": "agent-xxx" } } |
| 注意 | id 是 uint64 字符串形式                          |

### 5.2 创建 PreAuthKey

| 项目 | 说明                                                     |
| ---- | -------------------------------------------------------- |
| 端点 | POST /api/v1/preauthkey                                  |
| 请求 | { "user": "123", "reusable": false, "ephemeral": false } |
| 响应 | { "preAuthKey": { "key": "abc...", "id": "..." } }       |
| 注意 | user 字段必须是 User ID（uint64），不是 User Name        |

### 5.3 常见错误

| 错误                                | 原因                     | 解决方案                           |
| ----------------------------------- | ------------------------ | ---------------------------------- |
| invalid value for uint64 field user | user 传了 Name 而不是 ID | 使用 ts_user_id，不是 ts_user_name |
| user not found                      | User 不存在              | 先创建 User                        |

## 6. 数据同步策略

### 6.1 何时同步

| 事件               | 同步操作                        |
| ------------------ | ------------------------------- |
| Agent/Desktop 注册 | 创建 User，存储 ts_user_id      |
| Agent/Desktop 连接 | 上报 ts_ip，查询存储 ts_node_id |
| Agent/Desktop 删除 | 调用 Headscale 删除 Node        |
| 分组变更           | 更新 ACL 规则                   |
| 权限变更           | 更新 ACL 规则                   |

### 6.2 数据一致性

| 场景            | 处理方式                     |
| --------------- | ---------------------------- |
| Headscale 重启  | Node 信息保留，无需重新注册  |
| Server 重启     | 从数据库恢复映射关系         |
| Node 被手动删除 | Agent/Desktop 重连时重新注册 |
| User 被手动删除 | 需要重新创建 User            |

## 7. 总结

### 7.1 关键要点

| 要点              | 说明                               |
| ----------------- | ---------------------------------- |
| User ID vs Name   | API 调用使用 ID，显示使用 Name     |
| Server 是中介     | Agent/Desktop 不直接认证 Headscale |
| PreAuthKey 是凭证 | 一次性使用，用于节点注册           |
| Node 是设备       | 每个连接的设备是一个 Node          |
| User 隔离策略     | 每个 Agent/Desktop 独立 User       |

### 7.2 User 隔离设计决策

Headscale 特性：同一 User 下的 Node 默认互通，无需 ACL。

| 方案            | 说明                             | 安全性 |
| --------------- | -------------------------------- | ------ |
| 同 User 互通    | 所有节点放同一 User，默认互通    | 低     |
| 独立 User + ACL | 每个节点独立 User，通过 ACL 授权 | 高     |

选择独立 User 方案的原因：

| 风险场景                  | 同 User 方案  | 独立 User 方案   |
| ------------------------- | ------------- | ---------------- |
| Desktop 越权访问 Agent    | ⚠️ 默认可访问 | ✅ 需要 ACL 授权 |
| Desktop 访问其他 Desktop  | ⚠️ 默认可访问 | ✅ 需要 ACL 授权 |
| 外部 Agent 访问内网 Agent | ⚠️ 默认可访问 | ✅ 需要 ACL 授权 |

### 7.3 映射关系总结

| Server          | Headscale | 关系 |
| --------------- | --------- | ---- |
| Agent           | User      | 1:1  |
| Agent           | Node      | 1:1  |
| Client (单设备) | User      | 1:1  |
| Client (单设备) | Node      | 1:1  |
| Client (多设备) | User      | 1:1  |
| DesktopInstance | Node      | 1:1  |

## 8. Agent 连接与认证设计（核心业务）

### 8.1 设计原则

| 原则                | 说明                                             |
| ------------------- | ------------------------------------------------ |
| PreAuthKey 随用随发 | 一次性门票，不存储，每次 Register 都发新的       |
| Agent 优先独立工作  | 能连 Headscale 就工作，不强依赖 Server 在线      |
| Headscale 保证 IP   | 同 User 下重复注册，Headscale 复用 Node，IP 不变 |
| 无状态备份          | 不备份 tailscaled.state，丢了就重新注册          |

### 8.2 PreAuthKey 特性

| 特性       | 说明                                      |
| ---------- | ----------------------------------------- |
| 一次性     | 使用后即失效，不可重复使用                |
| 有过期时间 | 创建时指定（建议 1 小时），过期后无法使用 |
| 临时对象   | 不持久化，Server 每次 Register 都发新的   |
| 幂等安全   | 多发不影响，Agent 用不到就自然过期        |

### 8.4 Agent 启动流程（核心）

Agent 启动时根据 Server 和 Headscale 的可用性，分为四种情况：

```txt
┌─────────────────────────────────────────────────────────────────────────────┐
│                     Agent 启动场景矩阵                                       │

│                        Headscale                                            │
│                    在线          离线                                        │
│              ┌────────────┬────────────┐                                    │
│   Server 在线│  正常启动  │  重试 TS   │                                    │
│              │  (场景 1)  │  (场景 2)  │                                    │
│              ├────────────┼────────────┤                                    │
│   Server 离线│  独立工作  │  世界末日  │                                    │
│              │  (场景 3)  │  (场景 4)  │                                    │
│              └────────────┴────────────┘                                    │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 场景 1: Server 在线、Headscale 在线（正常启动）

#### 场景 2: Server 在线、Headscale 离线（重试 TS）

```txt
│   Agent 启动                                                                │
│        │                                                                    │
│        ▼                                                                    │
│   有本地状态 ──► 直接连 Headscale ──► 成功 ──► 工作                         │
│        │                                                                    │
│        ▼                                                                    │
│   后台任务: 定时重试连接 Server，直到恢复                                   │
│                                                                             │
│   ⚠️ 如果无本地状态，无法获取 Key，进入场景 4                               │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 8.5 Server Register 处理逻辑

```txt
┌─────────────────────────────────────────────────────────────────────────────┐
│                     Server 处理 Register 请求                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   收到 Agent Register 请求                                                  │
│        │                                                                    │
│        ▼                                                                    │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ 1. 验证 agent_name + agent_token                                     │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│        │                                                                    │
│        ▼                                                                    │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ 2. 获取或创建 Headscale User                                         │   │
│   │    - 已有 ts_user_id: 直接使用                                       │   │
│   │    - 没有: 创建 User，存储 ts_user_id                                │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│        │                                                                    │
│        ▼                                                                    │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ 3. 创建新 PreAuthKey（每次都创建）                                   │   │
│   │                                                                     │   │
│   │    - user: ts_user_id（必须是 ID，不是 Name）                        │   │
│   │    - ephemeral: false（持久化节点）                                  │   │
│   │    - reusable: false（一次性）                                       │   │
│   │    - expiration: 1 小时（短期有效）                                  │   │
│   │                                                                     │   │
│   │    ⚠️ 不判断 Agent 是否已注册过，统一发新 Key                        │   │
│   │    ⚠️ Agent 如果已有状态，这个 Key 会被忽略，自然过期                │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│        │                                                                    │
│        ▼                                                                    │
│   返回: { authKey, controlURL, derpURL }                                    │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 8.6 故障场景处理

| 场景                       | 处理方式                                     | IP 变化 |
| -------------------------- | -------------------------------------------- | ------- |
| Server 掉线                | Agent 继续连 Headscale 工作，后台重试 Server | 不变    |
| Agent 重启，本地状态在     | 直接连 Headscale，不需要 Server              | 不变    |
| Agent 重启，本地状态丢失   | Register 拿 Key，Headscale 复用 Node         | 不变    |
| Agent 首次安装             | Register 拿 Key，Headscale 创建 Node         | 新分配  |
| Agent 启动时 Server 不可用 | 有本地状态则工作，无则等待 Server 恢复       | -       |

### 8.7 状态丢失时 Headscale 的行为（关键）

```txt
┌─────────────────────────────────────────────────────────────────────────────┐
│                     状态丢失时 Headscale 的行为                              │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   Agent 状态丢失（重装系统、删除状态文件）                                   │
│        │                                                                    │
│        ▼                                                                    │
│   Agent 调用 Register 获取新 PreAuthKey                                     │
│        │                                                                    │
│        ▼                                                                    │
│   Agent 使用新 Key 连接 Headscale                                           │
│        │                                                                    │
│        ▼                                                                    │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ Headscale 检查该 User 下是否已有 Node                                │   │
│   │                                                                     │   │
│   │ - 有 Node: 复用已有 Node，保持原 IP                                  │   │
│   │ - 无 Node: 创建新 Node，分配新 IP                                    │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│        │                                                                    │
│        ▼                                                                    │
│   结果: IP 不变（因为 User 下已有 Node）                                    │
│                                                                             │
│   ⚠️ 所以不需要备份 tailscaled.state                                        │
│   ⚠️ 状态丢了就丢了，重新注册，Headscale 会复用 Node                        │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 8.8 关键结论

| 问题                          | 答案                                     |
| ----------------------------- | ---------------------------------------- |
| Agent 创建时生成 PreAuthKey？ | 不生成，等 Agent 连接时再发              |
| Register 时判断是否首次？     | 不判断，统一发新 Key                     |
| 需要备份 tailscaled.state？   | 不需要，Headscale 会复用 Node            |
| 状态丢失 IP 会变吗？          | 不会，同 User 下 Headscale 复用已有 Node |
| Server 掉线影响 Agent？       | 不影响，Agent 独立连 Headscale 工作      |
| PreAuthKey 有效期多长？       | 建议 1 小时，反正是按需创建              |

### 8.9 与现有实现的差异

| 项目              | 现有实现            | 建议改进                          |
| ----------------- | ------------------- | --------------------------------- |
| Agent 创建时      | 立即生成 PreAuthKey | 不生成，延迟到 Register           |
| PreAuthKey 有效期 | 24 小时             | 1 小时（按需创建，短期即可）      |
| 状态备份          | 定期备份到 Server   | 删除，不需要                      |
| Agent 启动优先级  | 先连 Server         | 先尝试连 Headscale，后台连 Server |

## 9. Node IP 固定机制

### 9.1 IP 固定原理

Headscale 的 Node IP 分配机制：

| 配置项    | 值    | IP 行为                       |
| --------- | ----- | ----------------------------- |
| ephemeral | true  | 节点断开后删除，重连分配新 IP |
| ephemeral | false | 节点持久化，重连保持原 IP     |

当前实现使用 `ephemeral: false`，确保 IP 固定。

### 9.2 IP 固定流程

```txt
┌─────────────────────────────────────────────────────────────────────────────┐
│                          Node IP 固定机制                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   首次连接                                                                   │
│   ─────────                                                                 │
│   1. Server 创建 PreAuthKey (ephemeral: false)                              │
│   2. Agent/Desktop 使用 Key 连接 Headscale                                  │
│   3. Headscale 分配 IP (如 100.64.0.1)                                      │
│   4. Headscale 创建持久化 Node 记录                                         │
│   5. Server 存储 ts_ip, ts_node_id                                          │
│                                                                             │
│   断线重连                                                                   │
│   ─────────                                                                 │
│   1. Agent/Desktop 断开连接                                                 │
│   2. Headscale 保留 Node 记录（因为 ephemeral: false）                       │
│   3. Agent/Desktop 重新连接                                                 │
│   4. Headscale 识别已有 Node，恢复原 IP (100.64.0.1)                        │
│   5. IP 保持不变                                                            │
│                                                                             │
│   对比 ephemeral: true                                                      │
│   ────────────────────                                                      │
│   1. Agent/Desktop 断开连接                                                 │
│   2. Headscale 删除 Node 记录                                               │
│   3. Agent/Desktop 重新连接                                                 │
│   4. Headscale 创建新 Node，分配新 IP (可能是 100.64.0.5)                   │
│   5. IP 变化，ACL 规则失效                                                  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 9.3 当前实现状态

| 组件    | ephemeral 设置 | IP 行为 | 说明                 |
| ------- | -------------- | ------- | -------------------- |
| Agent   | false          | 固定    | 服务地址稳定         |
| Desktop | false          | 固定    | ACL 规则基于 IP 生效 |

### 9.4 IP 固定的重要性

| 场景       | 无 IP 固定                 | 有 IP 固定        |
| ---------- | -------------------------- | ----------------- |
| 服务访问   | 重连后 IP 变化，服务不可达 | IP 不变，服务稳定 |
| ACL 规则   | 重连后规则失效，需重新生成 | 规则持续有效      |
| 多设备管理 | 无法区分设备               | 每设备固定 IP     |
| 故障恢复   | 需要更新所有相关配置       | 自动恢复          |

### 9.5 注意事项

| 事项      | 说明                                |
| --------- | ----------------------------------- |
| Node 删除 | 手动删除 Node 后，重连会分配新 IP   |
| User 删除 | 删除 User 会级联删除其下所有 Node   |
| IP 池耗尽 | 长期不清理会导致 IP 池耗尽          |
| 定期清理  | 建议定期清理长期离线的 Node 释放 IP |

## 10. Tag 与 ACL 业务设计

### 10.1 Tag 设计原则

Tag 属于 Node（不是 User），用于 ACL 分组控制。

| 原则          | 说明                                  |
| ------------- | ------------------------------------- |
| 身份 Tag 唯一 | 每个 Agent/Desktop 有唯一身份 Tag     |
| 分组 Tag 多值 | 一个节点可属于多个分组                |
| Tag 命名规范  | 使用 name 而非 id，便于阅读           |
| ACL 基于 Tag  | 用 Tag 做访问控制，不用写一堆 IP 地址 |

### 10.2 Agent Tag 设计

| Tag 类型 | 格式                           | 说明            |
| -------- | ------------------------------ | --------------- |
| 身份 Tag | `tag:agent-id-{agent.name}`    | 每个 Agent 唯一 |
| 分组 Tag | `tag:agent-group-{group.name}` | 可属于多个分组  |

**示例：**

```txt
Agent: k8s-prod
Tags: [
  "tag:agent-id-k8s-prod",         ← 身份 Tag（唯一）
  "tag:agent-group-internal",      ← 分组 Tag
  "tag:agent-group-production"     ← 分组 Tag（可多个）
]
```

### 10.3 Desktop Tag 设计

| Tag 类型 | 格式                             | 说明              |
| -------- | -------------------------------- | ----------------- |
| 身份 Tag | `tag:desktop-id-{client.id}`     | 每个 Desktop 唯一 |
| 分组 Tag | `tag:desktop-group-{group.name}` | 可属于多个分组    |

**示例：**

```txt
Desktop: zhangsan@company.com
Tags: [
  "tag:desktop-id-zhangsan",       ← 身份 Tag（唯一）
  "tag:desktop-group-dev",         ← 分组 Tag
  "tag:desktop-group-ops"          ← 分组 Tag（可多个）
]
```

### 10.4 ACL 业务规则

#### 业务 1: Agent 同组互访

**需求：** 同一分组的 Agent 可以互访所有端口

**触发时机：** 创建 Agent 分组时，Server 自动创建 ACL

**ACL 规则：**

```txt
{
  "action": "accept",
  "src": ["tag:agent-group-{group.name}"],
  "dst": ["tag:agent-group-{group.name}:*"]
}
```

**示例：**

```txt
创建分组: internal
自动生成 ACL:
{
  "action": "accept",
  "src": ["tag:agent-group-internal"],
  "dst": ["tag:agent-group-internal:*"]
}

效果: internal 组的所有 Agent 可以互访所有端口
```

#### 业务 2: Agent 整个开放给 Desktop 分组

**需求：** 将 Agent 分组的所有端口开放给 Desktop 分组

**触发时机：** 管理员授权时

**ACL 规则：**

```txt
{
  "action": "accept",
  "src": ["tag:desktop-group-{desktop_group.name}"],
  "dst": ["tag:agent-group-{agent_group.name}:*"]
}
```

**示例：**

```txt
授权: desktop-group-dev → agent-group-internal (全部端口)
生成 ACL:
{
  "action": "accept",
  "src": ["tag:desktop-group-dev"],
  "dst": ["tag:agent-group-internal:*"]
}

效果: dev 组的所有 Desktop 可以访问 internal 组的所有 Agent 的所有端口
```

#### 业务 3: Agent 特定端口开放给 Desktop 分组

**需求：** 将 Agent 分组的特定端口开放给 Desktop 分组

**触发时机：** 管理员授权时

**ACL 规则：**

```txt
{
  "action": "accept",
  "src": ["tag:desktop-group-{desktop_group.name}"],
  "dst": ["tag:agent-group-{agent_group.name}:{port}"]
}
```

**示例：**

```txt
授权: desktop-group-dev → agent-group-internal:3306
生成 ACL:
{
  "action": "accept",
  "src": ["tag:desktop-group-dev"],
  "dst": ["tag:agent-group-internal:3306"]
}

效果: dev 组的所有 Desktop 可以访问 internal 组的所有 Agent 的 3306 端口
```

#### 业务 4: 单个 Agent 开放给 Desktop 分组

**需求：** 将特定 Agent 的端口开放给 Desktop 分组

**触发时机：** 管理员授权时

**ACL 规则：**

```txt
{
  "action": "accept",
  "src": ["tag:desktop-group-{desktop_group.name}"],
  "dst": ["tag:agent-id-{agent.name}:{port}"]
}
```

**示例：**

```txt
授权: desktop-group-dev → agent-id-k8s-prod:3306
生成 ACL:
{
  "action": "accept",
  "src": ["tag:desktop-group-dev"],
  "dst": ["tag:agent-id-k8s-prod:3306"]
}

效果: dev 组的所有 Desktop 可以访问 k8s-prod 这个 Agent 的 3306 端口
```

### 10.5 ACL 规则汇总

| 业务                          | src                        | dst                                | 触发时机        |
| ----------------------------- | -------------------------- | ---------------------------------- | --------------- |
| Agent 同组互访                | `tag:agent-group-{name}`   | `tag:agent-group-{name}:*`         | 创建 Agent 分组 |
| Agent 组全开放给 Desktop 组   | `tag:desktop-group-{name}` | `tag:agent-group-{name}:*`         | 授权时          |
| Agent 组特定端口给 Desktop 组 | `tag:desktop-group-{name}` | `tag:agent-group-{name}:{port}`    | 授权时          |
| 单个 Agent 端口给 Desktop 组  | `tag:desktop-group-{name}` | `tag:agent-id-{agent.name}:{port}` | 授权时          |

### 10.6 Server 维护 ACL 的时机

| 事件             | ACL 操作                        |
| ---------------- | ------------------------------- |
| 创建 Agent 分组  | 添加同组互访规则                |
| 删除 Agent 分组  | 删除同组互访规则 + 相关授权规则 |
| Agent 加入分组   | 更新 Agent 的 Tags              |
| Agent 离开分组   | 更新 Agent 的 Tags              |
| 创建授权         | 添加对应 ACL 规则               |
| 删除授权         | 删除对应 ACL 规则               |
| Desktop 加入分组 | 更新 Desktop 的 Tags            |
| Desktop 离开分组 | 更新 Desktop 的 Tags            |
