# SSH 工具设计

> 版本：v0.3.0

## 1. 概述

用户通过 Desktop 客户端访问内网 SSH 服务时，无需管理 SSH Key，系统自动处理认证。

## 2. 技术选型：使用 Tailscale SSH

经过源码分析，Tailscale 已内置完整的 SSH 服务器实现，Headscale 也完整支持 SSHPolicy。因此采用 Tailscale 原生 SSH 功能，无需自行开发。

| 对比项     | 自研方案   | Tailscale SSH                          |
| ---------- | ---------- | -------------------------------------- |
| 开发量     | 高         | 零                                     |
| 安全性     | 需自行保证 | Tailscale 保证                         |
| 功能完整性 | 需逐步实现 | 完整支持端口转发、Agent 转发、会话录制 |
| 维护成本   | 高         | 低                                     |

## 4. tsnet 与 Tailscale SSH 的关系

当前 Agent 使用 tsnet 库（Tailscale 的嵌入式库）实现网络隧道。tsnet 本身不直接包含 SSH 服务，但可以通过配置启用。

| 组件         | 说明                                           |
| ------------ | ---------------------------------------------- |
| tsnet.Server | 嵌入式 Tailscale 客户端，提供 Listen/Dial 能力 |
| tailssh      | Tailscale 内置的 SSH 服务器模块，独立于 tsnet  |
| LocalBackend | tsnet 内部的后端，管理 Prefs 配置              |

tsnet 启用 SSH 的条件：

1. 编译时链接 tailssh 模块（通过 import 触发 init 注册）
2. 运行时设置 RunSSH = true（通过 LocalClient.EditPrefs）
3. Headscale 下发包含 SSH 规则的 Policy

## 5. 两种 SSH 访问场景

根据目标机器是否能上网，分为两种场景：

```
场景 A：SSH 到 Agent 本机
──────────────────────────

SSH Client ──▶ Desktop ══Tailscale══▶ Agent (Tailscale SSH)
                                         │
                                         ▼
                                      Shell

认证：Tailscale 身份（无需密码/密钥）


场景 B：SSH 到内网无法上网的机器
────────────────────────────────

SSH Client ──▶ Desktop ══Tailscale══▶ Agent ──TCP──▶ 内网 SSH 机器
                                      (代理)        (无法上网)
                                                        │
                                                        ▼
                                                     Shell

认证：Tailscale ACL + 目标机器密码/密钥
```

| 场景 | 目标机器                 | Agent 角色    | 认证方式                     |
| ---- | ------------------------ | ------------- | ---------------------------- |
| A    | Agent 本机               | SSH 服务端    | Tailscale 身份               |
| B    | 内网其他机器（无法上网） | SSH 代理/跳板 | Tailscale ACL + 目标机器认证 |

### 5.1 场景 A：SSH 到 Agent 本机

适用于 Agent 机器本身就是目标机器的情况。

Tailscale SSH 的优势：

- 无需在 Agent 机器上安装/配置 OpenSSH
- 无需管理 SSH Key，基于 Tailscale 身份认证
- 权限由 Headscale Policy 统一管理
- 支持会话录制、端口转发等高级功能

### 5.2 场景 B：SSH 到内网无法上网的机器

适用于目标 SSH 机器无法连接外网，无法安装 Tailscale 的情况。

Agent 充当 SSH 代理角色，监听服务端口并转发到内网目标机器：

```
配置示例：
├─ Agent 服务端口: 10022
├─ 内网目标地址: 192.168.1.10:22
└─ 用户连接: ssh root@100.64.0.5 -p 10022
```

**两层认证**

1. Tailscale ACL：验证 Desktop 是否有权访问 Agent:10022
2. SSH 认证：用户提供目标机器的密码或密钥

**端口冲突问题说明**

如果 Agent 机器上已经运行了 OpenSSH（监听 0.0.0.0:22），Tailscale SSH 不会产生冲突：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  Agent 机器上的两个 SSH 服务（互不冲突）                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │                        物理网卡 eth0                                 │   │
│  │                        192.168.1.100                                │   │
│  │                              │                                      │   │
│  │                              ▼                                      │   │
│  │                     ┌────────────────┐                              │   │
│  │                     │   OpenSSH      │                              │   │
│  │                     │   0.0.0.0:22   │  ◀── 传统 SSH，需要密钥      │   │
│  │                     └────────────────┘                              │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │                     Tailscale 虚拟网卡 tailscale0                    │   │
│  │                        100.64.0.5                                   │   │
│  │                              │                                      │   │
│  │                              ▼                                      │   │
│  │                     ┌────────────────┐                              │   │
│  │                     │ Tailscale SSH  │                              │   │
│  │                     │ 100.64.0.5:22  │  ◀── 基于身份认证，无需密钥  │   │
│  │                     └────────────────┘                              │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  关键点：                                                                   │
│  - OpenSSH 监听在物理网卡（或 0.0.0.0）                                     │
│  - Tailscale SSH 只监听在 Tailscale 虚拟网卡（100.64.x.x）                  │
│  - 两者使用不同的网络接口，端口 22 不冲突                                   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

| 连接方式               | 目标地址        | 响应服务      | 认证方式           |
| ---------------------- | --------------- | ------------- | ------------------ |
| ssh root@192.168.1.100 | 物理 IP:22      | OpenSSH       | 密码/密钥          |
| ssh root@100.64.0.5    | Tailscale IP:22 | Tailscale SSH | Tailscale 身份认证 |

因此，即使 Agent 机器已有 OpenSSH 服务，启用 Tailscale SSH 也完全安全，两者独立运行。

**内网 SSH vs Tailscale SSH**

两种 SSH 访问方式完全独立，互不影响：

| 访问方式      | 网络路径                  | 认证方式           | 适用场景       |
| ------------- | ------------------------- | ------------------ | -------------- |
| 内网直连      | 物理网络 192.168.x.x:22   | 密码/密钥          | 在同一内网时   |
| Tailscale SSH | Tailscale 隧道 100.64.x.x | Tailscale 身份认证 | 跨网络远程访问 |

**SFTP/SCP 工具支持（WinSCP 等）**

Tailscale SSH 完整支持 SFTP 子系统，WinSCP、FileZilla 等工具可直接使用：

| 场景                  | 工具连接地址   | 通道                        | 响应服务            |
| --------------------- | -------------- | --------------------------- | ------------------- |
| 直连 Agent            | 100.64.0.5:22  | Tailscale 隧道              | Agent Tailscale SSH |
| 转发到内网 SSH 服务器 | 127.0.0.1:2222 | Tailscale 隧道 + Agent 转发 | 内网 OpenSSH        |

两种方式对 SFTP/SCP 工具透明，因为底层都是标准 SSH 协议。

## 7. 工作流程

1. 用户在 Desktop 上使用任意 SSH 客户端，连接 Agent 的 Tailscale IP
2. 连接通过 Tailscale 隧道到达 Agent
3. Agent 的 Tailscale SSH 服务验证来源是否为合法 Tailscale 节点
4. 从 Headscale 获取 SSHPolicy，检查权限
5. 根据策略映射 SSH 用户名到本地用户
6. 启动 Shell 会话

## 8. SSHPolicy 配置

在 Headscale Policy 中添加 SSH 规则：

| 字段   | 说明              | 示例                            |
| ------ | ----------------- | ------------------------------- |
| action | 动作              | accept / check                  |
| src    | 来源              | group:admins, tag:desktop-xxx   |
| dst    | 目标              | tag:agent-xxx, autogroup:self   |
| users  | 允许的 SSH 用户名 | root, ubuntu, autogroup:nonroot |

## 9. 内网 SSH 服务配置（场景 B 详解）

### 9.1 数据模型

内网 SSH 服务作为普通 TCP 服务管理，复用现有 Service 模型：

| 字段        | 说明           | 示例             |
| ----------- | -------------- | ---------------- |
| Name        | 服务名称       | ssh-db-server    |
| Type        | 服务类型       | tcp              |
| AgentID     | 所属 Agent     | 1                |
| LocalAddr   | 内网目标地址   | 192.168.1.10     |
| LocalPort   | 内网目标端口   | 22               |
| RemotePort  | Agent 服务端口 | 10022            |
| Description | 描述           | 数据库服务器 SSH |

### 9.2 连接架构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    内网 SSH 服务连接架构                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌──────────────┐                                                           │
│  │ SSH 客户端    │  ssh root@100.64.0.5 -p 10022                            │
│  │ (PuTTY 等)   │                                                           │
│  └──────┬───────┘                                                           │
│         │                                                                   │
│         ▼                                                                   │
│  ┌──────────────┐     Tailscale 隧道      ┌──────────────────────────────┐ │
│  │   Desktop    │ ───────────────────────▶│           Agent              │ │
│  │ 100.64.0.10  │                         │  ┌────────────────────────┐  │ │
│  └──────────────┘                         │  │   TCP 代理服务         │  │ │
│                                           │  │                        │  │ │
│                                           │  │  监听: 0.0.0.0:10022   │  │ │
│                                           │  │  转发: 192.168.1.10:22 │  │ │
│                                           │  └───────────┬────────────┘  │ │
│                                           │  100.64.0.5  │               │ │

│                                                          │                 │
│                                                          ▼ TCP 转发        │

└─────────────────────────────────────────────────────────────────────────────┘
```

### 9.3 ACL 规则生成

内网 SSH 服务的 ACL 规则与普通 TCP 服务相同：

| 授权类型                | ACL Src                   | ACL Dst                 |
| ----------------------- | ------------------------- | ----------------------- |
| 服务授权给 Desktop      | tag:desktop-{client}      | tag:agent-{agent}:10022 |
| 服务授权给 Desktop 分组 | tag:desktop-group-{group} | tag:agent-{agent}:10022 |

### 9.4 认证流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    内网 SSH 认证流程                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  第一层：Tailscale ACL 认证                                                  │
│  ─────────────────────────                                                  │
│  Desktop 连接 Agent:10022 时，Tailscale 检查 ACL 规则                        │
│  ├─ 通过 → 允许 TCP 连接                                                    │
│  └─ 拒绝 → 连接被阻断                                                       │
│                                                                             │
│  第二层：SSH 认证（目标机器）                                                │
│  ─────────────────────────                                                  │
│  TCP 连接建立后，SSH 协议层认证                                              │
│  ├─ 密码认证：用户输入目标机器的密码                                         │
│  └─ 密钥认证：用户使用目标机器的 SSH 密钥                                    │
│                                                                             │
│  注意：第二层认证是目标机器的认证，与 Tailscale 无关                          │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 9.5 与 Tailscale SSH 的区别

| 对比项       | Tailscale SSH（场景 A）       | Agent 代理转发（场景 B） |
| ------------ | ----------------------------- | ------------------------ |
| 目标机器     | Agent 本机                    | 内网其他机器             |
| 目标机器要求 | 可上网，运行 Tailscale        | 无要求，可完全离线       |
| SSH 认证     | Tailscale 身份，无需密码/密钥 | 目标机器的密码/密钥      |
| 会话录制     | 支持                          | 不支持（透明转发）       |
| 端口转发     | 支持                          | 支持（SSH 协议层）       |
| 配置复杂度   | 低（自动）                    | 中（需创建服务）         |

## 10. 实现步骤

### 10.1 场景 A：Tailscale SSH（SSH 到 Agent 本机）

1. Agent 启动时启用 Tailscale SSH（导入 tailssh 模块，设置 RunSSH=true）
2. 扩展 ACL 同步逻辑，根据权限配置生成 SSH 规则
3. Desktop 提供 SSH 连接入口（可选，用户也可直接用 SSH 客户端）

### 10.2 场景 B：Agent 代理转发（SSH 到内网机器）

1. 复用现有 TCP 服务模型，创建 SSH 类型服务
2. Agent 启动 TCP 代理监听服务端口
3. ACL 同步逻辑生成服务端口的访问规则
4. Desktop 用户通过 Agent Tailscale IP + 服务端口连接
