# 访问控制系统设计

## 当前状态

**调试模式**：所有服务默认为 public，任何认证用户都可以访问所有服务。

## 未来设计

### 权限模型

每个 STCP 实例（服务）有三种访问权限：

1. **public** - 公开服务
   - 任何认证用户都可以访问
   - 适用于团队共享的开发环境

2. **private** - 私有服务
   - 只有明确授权的用户可以访问
   - 通过 `stcp_access` 表管理访问权限
   - 适用于个人开发环境或敏感服务

3. **group** - 组权限
   - 属于特定组的用户可以访问
   - 需要实现用户组管理功能
   - 适用于团队协作场景

### 数据库设计

详细的表结构定义见 [design_database.md](design_database.md)。

#### 需要的表

1. **`stcp_instances` 表（修改）**
   - 添加 `access_type` 字段：'public', 'private', 'group'
   - 添加 `group_id` 字段：当 access_type = 'group' 时关联到组

2. **`groups` 表（新增）**
   - 用户组管理
   - 包含组名称、描述等基本信息

3. **`group_members` 表（新增）**
   - 组成员关系
   - 支持角色（admin/member）

### API 设计

详细的 API 定义见 [design_api.md](design_api.md)。

#### 需要的 API

**组管理 API**（管理员）
- 创建、查询、更新、删除用户组
- 管理组成员（添加、移除）

**STCP 实例权限 API**（管理员）
- 设置实例的访问权限类型（public/private/group）
- 为 private 实例授权/撤销特定用户访问

**Client 服务查询 API**
- 获取可访问的服务列表（需要根据权限过滤）
  - public 服务：所有认证用户可见
  - private 服务：只有被授权的用户可见
  - group 服务：只有组成员可见

### 权限检查逻辑

**GetServices API 实现要求**：

1. 从 token 中获取当前用户的 client_id
2. 查询三类服务并合并返回：
   - **public 服务**：查询 `access_type = 'public'` 的所有实例
   - **private 服务**：通过 `stcp_access` 表查询用户有权限的实例
   - **group 服务**：通过 `group_members` 表查询用户所在组的实例
3. 合并结果并返回给客户端

**连接检查要求**：

当 Client 尝试连接 STCP 服务时，需要验证：
- public 服务：直接允许
- private 服务：检查 `stcp_access` 表是否有记录
- group 服务：检查用户是否在对应的组中

## 当前状态

**调试模式**（当前）：
- 所有服务默认为 public
- `GetServices` API 返回所有服务
- 不检查权限

**生产模式**（未来）：
- 新服务默认为 private
- 根据 access_type 过滤服务
- 支持组权限管理

## 安全考虑

1. **默认安全**：新创建的服务默认为 `private`
2. **审计日志**：记录权限变更历史
3. **最小权限原则**：用户只能看到有权限的服务
4. **组管理权限**：只有组管理员可以添加/移除成员
