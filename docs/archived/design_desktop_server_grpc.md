# Desktop Server gRPC 设计

> 本文档描述 Desktop 客户端与 Server 之间的 gRPC 通信设计，基于 Desktop Web 重构方案和 Server Web 重构方案。

## 1. 设计概述

### 1.1 通信架构

Desktop 客户端通过两个独立的通道与 Server 通信：

| 通道        | 协议      | 职责                                 |
| ----------- | --------- | ------------------------------------ |
| gRPC 通道   | gRPC      | 管理通信：登录、认证、心跳、数据同步 |
| Tunnel 通道 | Tailscale | 数据传输：访问内网服务的实际流量     |

```txt
┌─────────────────┐                              ┌─────────────────┐
│                 │         gRPC 通道            │                 │
│     Desktop     │◄────────────────────────────►│     Server      │
│                 │    (管理、认证、数据同步)     │                 │
│                 │                              │                 │
│                 │       Tailscale 通道         │                 │
│                 │◄────────────────────────────►│   (Headscale)   │
│                 │      (内网服务访问)          │                 │
└─────────────────┘                              └─────────────────┘
```

### 1.2 数据分类

| 数据类型 | 说明                         | 获取方式              |
| -------- | ---------------------------- | --------------------- |
| 静态数据 | 服务列表、设备列表等基础数据 | 登录时获取 + 手动刷新 |
| 动态数据 | 服务状态、主机在线状态       | 心跳流实时推送        |

## 2. 登录业务

### 2.1 业务流程

```txt
┌─────────────────┐                              ┌─────────────────┐
│     Desktop     │                              │     Server      │
└────────┬────────┘                              └────────┬────────┘
         │                                                │
         │  1. Login(client_name, client_secret,          │
         │     device_name, device_fingerprint,           │
         │     system_info)                               │
         │───────────────────────────────────────────────►│
         │                                                │
         │                                    2. 验证 User (Client 角色)
         │                                    3. 验证 Client Secret
         │                                    4. 查找或创建 Node
         │                                    5. 生成 Desktop Secret
         │                                    6. 创建 Tailscale PreAuthKey
         │                                                │
         │  LoginResponse(desktop_id, secret,             │
         │     auth_key, server_url,                      │
         │     services, devices)                         │
         │◄───────────────────────────────────────────────│
         │                                                │
         │  7. 保存凭据到本地                             │
         │  8. 使用 auth_key 连接 Tailscale               │
         │                                                │
         │  9. Heartbeat Stream (建立心跳流)              │
         │───────────────────────────────────────────────►│
         │                                                │
```

### 2.2 登录请求

| 字段               | 类型              | 说明                     |
| ------------------ | ----------------- | ------------------------ |
| client_name        | string            | Client 用户名            |
| client_secret      | string            | Client 认证密钥          |
| device_name        | string            | 设备名称（主机名）       |
| device_fingerprint | string            | 设备指纹（硬件唯一标识） |
| system_info        | DesktopSystemInfo | 系统信息                 |

系统信息字段：

| 字段       | 类型   | 说明                           |
| ---------- | ------ | ------------------------------ |
| os         | string | 操作系统：linux/windows/darwin |
| os_version | string | 系统版本                       |
| arch       | string | CPU 架构：amd64/arm64          |
| hostname   | string | 主机名                         |
| cpu        | string | CPU 型号                       |
| cpu_cores  | int32  | CPU 核心数                     |
| memory_gb  | int32  | 内存大小（GB）                 |

### 2.3 登录响应

| 字段       | 类型                | 说明                             |
| ---------- | ------------------- | -------------------------------- |
| success    | bool                | 是否成功                         |
| message    | string              | 响应消息                         |
| desktop_id | uint64              | Desktop Node ID                  |
| secret     | string              | Desktop 专属密钥（用于后续认证） |
| auth_key   | string              | Tailscale PreAuthKey             |
| server_url | string              | Headscale 服务器地址             |
| services   | []AuthorizedService | 已授权服务列表（静态数据）       |
| devices    | []DesktopDevice     | 我的设备列表（静态数据）         |

### 2.4 自动登录（Token 认证）

已登录过的设备使用保存的凭据自动认证：

```txt
┌─────────────────┐                              ┌─────────────────┐
│     Desktop     │                              │     Server      │
└────────┬────────┘                              └────────┬────────┘
         │                                                │
         │  1. Authenticate(desktop_id, secret,           │
         │     device_fingerprint, system_info)           │
         │───────────────────────────────────────────────►│
         │                                                │
         │                                    2. 验证 Node 存在
         │                                    3. 验证 Desktop Secret
         │                                    4. 验证设备指纹（可选）
         │                                    5. 更新 Node 信息
         │                                                │
         │  AuthenticateResponse(success,                 │
         │     auth_key, server_url,                      │
         │     services, devices)                         │
         │◄───────────────────────────────────────────────│
         │                                                │
```

## 3. 我的服务

### 3.1 数据架构总览

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                                    我的服务数据架构                                      │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  ┌─────────────┐                       ┌─────────────┐                                  │
│  │   Desktop   │                       │   Server    │                                  │
│  └──────┬──────┘                       └──────┬──────┘                                  │
│         │                                     │                                         │
│         │  ① 登录/认证                        │                                         │
│         │────────────────────────────────────►│                                         │
│         │                                     │  查询 DB: proxy_service + acl_*         │
│         │  ② 返回静态数据 (services)          │                                         │
│         │◄────────────────────────────────────│                                         │
│         │                                     │                                         │
│         │  ③ 建立心跳流                       │                                         │
│         │◄───────────────────────────────────►│                                         │
│         │                                     │                                         │
│         │  ④ 心跳响应推送动态数据              │  查询内存: AgentConnection              │
│         │◄────────────────────────────────────│         + ServiceStatusCache            │
│         │     (service_status)                │                                         │
│         │                                     │                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 静态数据：服务列表

登录/认证时从数据库查询，包含用户已授权的所有服务。

#### 3.2.1 服务列表字段定义

| 字段        | 类型   | 数据来源                                        | 说明                          |
| ----------- | ------ | ----------------------------------------------- | ----------------------------- |
| id          | string | proxy_service.id                                | 服务唯一标识                  |
| name        | string | proxy_service.name                              | 服务名称（如 MySQL）          |
| agent_id    | uint64 | proxy_service.user_id                           | 所属 Agent 用户 ID            |
| agent_name  | string | user.alias (JOIN user ON proxy_service.user_id) | 所属 Agent 别名               |
| listen_addr | string | proxy_service.source_addr                       | 访问地址（100.64.0.1:3306）   |
| target_addr | string | proxy_service.target_addr                       | 目标地址（192.168.1.10:3306） |

#### 3.2.2 授权查询逻辑

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                              服务授权查询流程                                            │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  输入：Client 用户 ID (client_id)                                                       │
│  输出：已授权服务 ID 列表                                                               │
│                                                                                         │
│  步骤 1：查询用户所属分组                                                               │
│  ┌─────────────────────────────────────────────────────────────────────────────────┐   │
│  │  表：group_member                                                               │   │
│  │  条件：user_id = {client_id}                                                    │   │
│  │  结果：group_ids = [1, 2, 3]                                                    │   │
│  └─────────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                         │
│  步骤 2：查询直接服务授权（授权给用户或用户所属分组）                                   │
│  ┌─────────────────────────────────────────────────────────────────────────────────┐   │
│  │  表：acl_service_permission                                                     │   │
│  │  条件：(target_type='user' AND target_id={client_id})                           │   │
│  │     OR (target_type='group' AND target_id IN {group_ids})                       │   │
│  │  结果：service_ids                                                              │   │
│  └─────────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                         │
│  步骤 3：查询用户授权（授权访问某 Agent 所有端口）                                      │
│  ┌─────────────────────────────────────────────────────────────────────────────────┐   │
│  │  表：acl_user_permission                                                        │   │
│  │  条件：(target_type='user' AND target_id={client_id})                           │   │
│  │     OR (target_type='group' AND target_id IN {group_ids})                       │   │
│  │  结果：agent_ids                                                                │   │
│  │                                                                                  │   │
│  │  然后查询：proxy_service WHERE user_id IN {agent_ids}                           │   │
│  └─────────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                         │
│  步骤 4：查询分组授权（授权访问某分组所有 Agent 的所有端口）                            │
│  ┌─────────────────────────────────────────────────────────────────────────────────┐   │
│  │  表：acl_group_permission                                                       │   │
│  │  条件：(target_type='user' AND target_id={client_id})                           │   │
│  │     OR (target_type='group' AND target_id IN {group_ids})                       │   │
│  │  结果：授权分组 IDs                                                             │   │
│  │                                                                                  │   │
│  │  然后查询：group_member WHERE group_id IN {授权分组} → 分组内 Agent IDs         │   │
│  │  然后查询：proxy_service WHERE user_id IN {分组内Agent}                         │   │
│  └─────────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                         │
│  步骤 5：合并去重                                                                       │
│  ┌─────────────────────────────────────────────────────────────────────────────────┐   │
│  │  最终服务列表 = 步骤2 ∪ 步骤3 ∪ 步骤4                                           │   │
│  └─────────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

### 3.3 动态数据：服务状态

通过心跳流实时推送，数据来源于 Server 内存缓存。

#### 3.3.1 服务状态字段定义

| 字段       | 类型   | 数据来源                              | 说明                          |
| ---------- | ------ | ------------------------------------- | ----------------------------- |
| service_id | string | 服务 ID                               | 对应静态数据中的 id           |
| status     | string | 计算得出（见 3.3.2）                  | running/stopped/error/offline |
| error_msg  | string | cache.ServiceStatusCache[id].ErrorMsg | 错误信息（status=error时）    |

#### 3.3.2 状态计算逻辑

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                              服务状态计算流程                                            │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  输入：service_id, agent_id                                                             │
│  输出：status, error_msg                                                                │
│                                                                                         │
│  ┌─────────────────────────────────────────────────────────────────────────────────┐   │
│  │  步骤 1：检查 Agent 是否在线                                                     │   │
│  │                                                                                  │   │
│  │  数据来源：AgentServiceServer.connections[agent_id]                              │   │
│  │                                                                                  │   │
│  │  判断条件：                                                                      │   │
│  │  - connections 中存在该 agent_id                                                 │   │
│  │  - connection.LastSeen 距今 < 60 秒                                              │   │
│  │                                                                                  │   │
│  │  如果 Agent 离线 → 返回 status="offline"                                         │   │
│  └─────────────────────────────────────────────────────────────────────────────────┘   │
│                          │                                                              │
│                          ▼ Agent 在线                                                   │
│  ┌─────────────────────────────────────────────────────────────────────────────────┐   │
│  │  步骤 2：查询服务运行状态                                                        │   │
│  │                                                                                  │   │
│  │  数据来源：cache.proxyServiceStatusCache[service_id]                             │   │
│  │                                                                                  │   │
│  │  缓存数据由 Agent 通过 ReportProxyStatus RPC 上报：                              │   │
│  │  - Agent 启动服务成功 → status="running"                                         │   │
│  │  - Agent 启动服务失败 → status="error", error_msg="..."                          │   │
│  │  - Agent 停止服务     → status="stopped"                                         │   │
│  │                                                                                  │   │
│  │  如果缓存不存在 → 返回 status="pending"（等待 Agent 上报）                       │   │
│  │  如果缓存存在   → 返回缓存中的 status 和 error_msg                               │   │
│  └─────────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

#### 3.3.3 状态值说明

| 状态值  | 含义         | 触发条件                        |
| ------- | ------------ | ------------------------------- |
| running | 服务正常运行 | Agent 在线 + Agent 上报 running |
| stopped | 服务已停止   | Agent 在线 + Agent 上报 stopped |
| error   | 服务异常     | Agent 在线 + Agent 上报 error   |
| pending | 等待启动     | Agent 在线 + 缓存无数据         |
| offline | Agent 离线   | Agent 心跳超时（>60秒）         |

#### 3.3.4 数据流转图

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                              服务状态数据流转                                            │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  ┌─────────┐    ReportProxyStatus    ┌─────────────────┐                               │
│  │  Agent  │────────────────────────►│ proxyService    │                               │
│  │         │    (service_id,         │ StatusCache     │                               │
│  │         │     status,             │ (内存)          │                               │
│  │         │     error_msg)          │                 │                               │
│  └─────────┘                         │ map[service_id] │                               │
│       │                              │  *RuntimeStatus │                               │
│       │                              └────────┬────────┘                               │
│       │                                       │                                         │
│       │ Heartbeat                             │ 查询                                    │
│       │ (每5秒)                               │                                         │
│       ▼                                       ▼                                         │
│  ┌─────────────────┐                 ┌─────────────────┐                               │
│  │ AgentConnection │                 │ Desktop 心跳    │                               │
│  │ (内存)          │────────────────►│ 响应生成        │                               │
│  │                 │  检查在线状态   │                 │                               │

│                                               │ 心跳响应                                │
│                                               ▼                                         │
│                                        ┌─────────────┐                                 │
│                                        │   Desktop   │                                 │
│                                        │             │                                 │
│                                        │ 更新 UI     │                                 │
│                                        └─────────────┘                                 │
│                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

## 5. 心跳流设计

### 5.1 双向流通信

```txt
┌─────────────────┐                              ┌─────────────────┐
│     Desktop     │                              │     Server      │
└────────┬────────┘                              └────────┬────────┘
         │                                                │
         │  HeartbeatRequest (每 5 秒)                    │
         │  - desktop_id                                  │
         │  - tunnel_ip                                   │
         │  - tunnel_connected                            │
         │───────────────────────────────────────────────►│
         │                                                │
         │                                    更新 Node 心跳时间
         │                                    检查数据变更
         │                                                │
         │  HeartbeatResponse                             │
         │  - service_status[]  (服务状态变更)            │
         │  - device_status[]   (设备状态变更)            │
         │  - data_version      (数据版本号)              │
         │◄───────────────────────────────────────────────│
         │                                                │
         │  (如果 data_version 变更，触发数据刷新)        │
         │                                                │
```

### 5.2 心跳请求

| 字段             | 类型   | 说明            |
| ---------------- | ------ | --------------- |
| desktop_id       | uint64 | Desktop Node ID |
| tunnel_ip        | string | 当前隧道 IP     |
| tunnel_connected | bool   | 隧道连接状态    |

### 5.3 心跳响应

| 字段           | 类型            | 说明                     |
| -------------- | --------------- | ------------------------ |
| service_status | []ServiceStatus | 服务状态列表（仅变更的） |
| device_status  | []DeviceStatus  | 设备状态列表（仅变更的） |
| data_version   | uint64          | 数据版本号               |

### 5.4 数据版本机制

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                                    数据版本机制                                          │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  Server 维护全局数据版本号 data_version，以下操作会递增版本：                           │
│                                                                                         │
│  1. 服务授权变更（新增/删除授权）                                                       │
│  2. 服务配置变更（新增/删除/修改服务）                                                  │
│  3. 用户分组变更（加入/退出分组）                                                       │
│                                                                                         │
│  Desktop 收到心跳响应后：                                                               │
│  - 如果 data_version 与本地不同，调用 RefreshData 重新获取完整数据                      │
│  - 如果 data_version 相同，仅更新状态数据                                               │
│                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

## 6. gRPC 接口定义

### 6.1 服务定义

```txt
DesktopService
├── Login              - 首次登录（Client 凭证）
├── Authenticate       - Token 认证（Desktop 凭证）
├── Heartbeat          - 心跳流（双向流）
├── RefreshServices    - 刷新服务列表
├── RefreshDevices     - 刷新设备列表
└── RevokeDevice       - 注销设备
```

### 6.2 接口说明

| 接口            | 类型     | 说明                         |
| --------------- | -------- | ---------------------------- |
| Login           | Unary    | 首次登录，返回凭据和初始数据 |
| Authenticate    | Unary    | Token 认证，返回初始数据     |
| Heartbeat       | BiStream | 双向流，实时状态同步         |
| RefreshServices | Unary    | 手动刷新服务列表             |
| RefreshDevices  | Unary    | 手动刷新设备列表             |
| RevokeDevice    | Unary    | 注销指定设备                 |

## 7. 数据同步策略

### 7.1 静态数据同步

| 触发时机   | 同步内容             |
| ---------- | -------------------- |
| 登录成功   | 服务列表、设备列表   |
| 认证成功   | 服务列表、设备列表   |
| 版本号变更 | 服务列表、设备列表   |
| 手动刷新   | 服务列表 或 设备列表 |

### 7.2 动态数据同步

| 数据类型    | 同步方式     | 频率 |
| ----------- | ------------ | ---- |
| 服务状态    | 心跳响应推送 | 5 秒 |
| 设备状态    | 心跳响应推送 | 5 秒 |
| gRPC 状态   | 本地检测     | 实时 |
| Tunnel 状态 | 本地检测     | 实时 |

## 8. 错误处理

### 8.1 gRPC 错误码

| 错误码            | 说明       | 处理方式           |
| ----------------- | ---------- | ------------------ |
| UNAUTHENTICATED   | 认证失败   | 跳转登录页         |
| NOT_FOUND         | 资源不存在 | 提示用户           |
| PERMISSION_DENIED | 权限不足   | 提示用户           |
| UNAVAILABLE       | 服务不可用 | 重试或离线模式     |
| INTERNAL          | 内部错误   | 提示用户联系管理员 |

### 8.2 连接断开处理

```txt
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                                    连接断开处理                                          │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                         │
│  1. 心跳流断开                                                                          │
│     - 自动重连（指数退避：1s, 2s, 4s, 8s, 最大 30s）                                    │
│     - 重连成功后重新建立心跳流                                                          │
│     - 重连失败超过 5 次，提示用户检查网络                                               │
│                                                                                         │
│  2. gRPC 连接断开                                                                       │
│     - 更新 gRPC 状态为离线                                                              │
│     - 使用本地缓存数据                                                                  │
│     - 后台持续尝试重连                                                                  │
│                                                                                         │
│  3. Tunnel 连接断开                                                                     │
│     - 更新 Tunnel 状态为离线                                                            │
│     - 服务连接功能不可用                                                                │
│     - 提示用户点击重连                                                                  │
│                                                                                         │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```
